# Astra Journey — передача дизайна главной страницы разработчику production

**Состояние:** разработаны 5 автономных концепций; конкретный вариант ещё не утверждён владельцем. **Не применять в production без отдельной задачи.**

## Визуальный эталон

Пять вариантов локально представлены в `index.html`, `styles.css`, `fixtures.js`, `app.js`. Для продолжения использовать только **одну концепцию после выбора владельцем**: `design-a`, `design-b`, `design-c`, `design-d` или `design-e`. Фикстуры и лабораторные UI-переключатели не являются частью production.

Рекомендация frontend-разработчика для дальнейшей оценки: **A · Mission Control** как наиболее сбалансированная: сохранены три крупных узнаваемых блока, ясная идентификация, телеметрия и быстрые действия; без потребности в новых игровых данных. Приоритет владельца может быть иным.

## Production-точки интеграции

- `internal/server/web/index.html`: текущая главная `#game`, `#welcome-name`, `#overview-level`, `#overview-xp`, `#overview-xp-text`, `#overview-upgrade`, `#overview-company`, `#credits`, `#balance-change`, `#location`, `#overview-region`, `#star-date`, `#connection`, `.overview-stats`, `.workspace-intro`.
- `internal/server/web/features/shell/app.js`: **оставить** `renderSnapshot()` и подписку на `snapshotaccepted`; сохранить `Session`, `I18n`, `Format`, вызов `profile/upgrade`, дельту баланса, `notificationchange`, правила disabled.
- `internal/server/web/features/shell/navigation.js`: **оставить** штатные `Modules.open`, `showgalaxy`, `data-open`, сайдбар, collapse и настройки плотности.
- `internal/server/web/ui/windows.js` и `core/preferences.js`: **не заменять** автономным оконным имитатором `app.js`. Сохранить перетаскивание, resize, z-index, pin и состояние расположения. 
- `internal/server/web/styles/terminal.css` и `styles/tokens.css`: переносить только scoping стили выбранной концепции. Не копировать глобальные `*`, `html`, `body`, `.shell`, `.demo-*`, mock `.window-*`.
- `internal/server/web/features/chat/index.js`: проверить поведение закреплённого чата в `home-lower-grid` / `chat-home-slot`; редизайн главной страницы не должен нарушать docking или резервированное место новостей.

## Инварианты

1. **Баланс** из `expedition.credits`, не из статических цифр.
2. **Текущая система** из `expedition.system.name`, а если корабль летит — текущая система со стрелкой на `ship.destination`; `overview-region` из `expedition.region`.
3. **Хронология** из `state.date`, локализация ЭД/ED, никаких новых игровых тиков.
4. **Стаж** `profile.level`, `xp`, `required_xp`, `upgrade_cost`. Действие `profile/upgrade` и серверные ограничения сохраняются. 
5. **Корпорация** `profile.company_tag`, `company_flag`, `company_color`, `company_flag_design`, а не учебный `[EDEN]`. Рисование `paintFlag` оставлять production-компоненту.
6. **Открытие модулей** следует штатному механизму: `data-open="galaxy"` с событием `showgalaxy` и `data-open="ship"` на `Modules.open`. Остальные быстрые действия должны соответствовать реально доступным ID.
7. **Сайдбар / навигация / чат / уведомления / авторизация** остаются самостоятельными production-компонентами.
8. **Сохранение размеров и положения окон** должно продолжать работать, включая `Preferences`.
9. **Безопасность:** не использовать данные игрока как HTML-код. `textContent`, действующий UI binding. Никакой несанкционированной утечки между аккаунтами.
10. **Доступность:** читаемый фокус, масштаб 1280/1366/1440/1920, не перекрывать открытые окна, переключение RU/EN, уменьшение анимации при `prefers-reduced-motion`.

## Не переносить

`fixtures.js`, `app.js` целиком, CSS mock `.window-layer/.mock-window`, тестовые кнопки «0/1/3 окна», селектор A–E, `#demo-refresh`, лабораторную оболочку, поддельные окна чата и корабля, воображаемые операции «обновление баланса» и «повышение стажа» на локальном состоянии. Никакие существующие production API и Go-сервисы не меняются на стадии выбора дизайна.

## Предлагаемая последовательность после утверждения

1. Привязать выбранную компоновку к *тем же* значениям DOM `index.html`; при переносе следить за `id`, используемыми в `app.js`.
2. Вынести нужные CSS-селекторы в production с областью `.command-home-*`, не меняя `.chat-*`, глобальные кнопки и dialogs.
3. Сохранить `renderSnapshot`, `Modules`, `Session`, `I18n`, `showgalaxy`, `profile/upgrade`, sidebar и chat-home docking.
4. Проверить пустую главную + 1 окно + 3 окна, открытый/закрепленный чат, минимальный viewport 1280×720, расширенный 1920×1080, быстрые изменения снимков, баланс, опыт, превышение уровней, разные аккаунты.
5. Добавить browser regression и сделать отдельный PR для production. Только владелец решает о слиянии.
