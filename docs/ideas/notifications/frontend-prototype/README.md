# Astra Journey — уведомления / автономный frontend-прототип

**Статус:** три интерактивных UX-варианта для согласования, **не production-реализация**.  
**Область:** только `docs/ideas/notifications/frontend-prototype/`.  
**Ветка разработки:** `frontend/notifications-ui-prototype` (PR без слияния).

## Как открыть

Откройте **`index.html`** в современном браузере двойным щелчком: все стили, данные и логика лежат рядом и подключаются относительными путями. Node.js, Python, npm, Go, PostgreSQL, NATS, Chat Service и интернет для самого интерфейса не требуются. Используются обычные HTML, CSS и JavaScript без ES-модулей, поэтому запуск с `file://` поддерживается.

Если браузер запрещает запуск локальных скриптов политиками безопасности, можно использовать только статический HTTP-сервер:

```bash
cd docs/ideas/notifications/frontend-prototype
python3 -m http.server 8766 --bind 127.0.0.1
# http://127.0.0.1:8766/
```

Это **не** запуск игры или mock-сервера, а лишь выдача четырёх статических файлов.

## Три варианта дизайна

| Вариант | Приём | Предназначение |
| --- | --- | --- |
| **A — Compact Chat Style** | 34 px заголовок, 11 px базовый шрифт, почти идентичные чату фоны, кнопки и разделители | **Рекомендуемый**: лучше всего ощущается как второй модуль рядом с чатом |
| **B — Notification Console** | метки `SYS/ECO/SCI/COR/OPS`, вертикальный акцент типа события, более моноширинная телеметрия | Для тех, кому важна визуальная категоризация событий |
| **C — Minimal Activity Feed** | спокойный фон, минимум границ, время + текст без служебной метки | Для тихой ленты без перегруженности |

Переключатель A/B/C меняет **только CSS-представление**, не сбрасывая уведомления, фильтр и статусы прочтения. Все варианты можно рассмотреть в **одной и той же интерактивной сцене**.

### Что можно попробовать

- Просмотреть группу **непрочитанных** и группу **прочитанных** событий.
- Переключать нижний фильтр «Все» / «Непрочитанные».
- Нажать ✓ справа от конкретного непрочитанного события — изменится счётчик.
- Нажать «✓ Прочитать всё» — все события станут прочитанными.
- Нажать на заголовок/текст строки — откроется подробный текст. Диалог закрывается через **Esc**; есть кнопка отметки прочитанным.
- Нажать «Пустой список» и «40 событий» для проверки крайних состояний и прокрутки.
- Создать новое тестовое событие или вернуть исходные 16 через «Сбросить данные».
- Перетащить демонстрационное окно за заголовок, изменить размер за правый нижний угол, свернуть, закрыть и открыть заново. Сфокусированный заголовок перемещается стрелками.
- Сменить «Компактный» / «Обычный» размер, а затем изменить размер окна браузера до мобильного.

По умолчанию: **16 вымышленных уведомлений**, **7 непрочитанных**, 5 категорий: системные, экономические, исследовательские, корпоративные и игровые. Данные меняются **только в памяти текущей страницы** и сбрасываются при её перезагрузке.

## На чём основан дизайн

Прочитаны фактические исходники на `main`:

- `AGENTS.md` и `docs/repository-organization.ru.md`;
- `internal/server/web/styles/tokens.css`;
- `scripts/frontend-generation/mock/chat-native.css` и `mock/chat-fragment.html`;
- `internal/server/web/features/chat/index.js`;
- `internal/server/web/features/notifications/index.js`;
- `internal/server/web/ui/windows.js`;
- `internal/notifications/notifications.go` (для последующего handoff).

Из чата взяты **параметры оформления**, но не сам DOM/JS чата: 34 px заголовок, компактные действия от 24 px, `Segoe UI`, базовый текст 11 px, тёмный фон `#171e26`, панель `#1c2935`, разделители `#40505b`, акцент `#efad58`, scrollbar с `overscroll-behavior: contain`. Нет подключений к реальному чату.

На этой стадии **не вызывается** `Modules.create()` — автономный прототип сам отрисовывает только демонстрационную оболочку окна. Рекомендуемая интеграция со штатным оконным менеджером, когда владелец утвердит дизайн, описана в [HANDOFF.md](HANDOFF.md).

## Проверки

Опционально, из этого каталога:

```bash
node test_contracts.cjs
CHROMIUM_PATH=/usr/bin/chromium python3 test_prototype.py
```

Для второго теста нужен `playwright` и установленный Chromium. Если `CHROMIUM_PATH` отсутствует, Playwright использует установленный им браузер. Тест загружает **точное содержимое локальных HTML/CSS/JS файлов** в Chromium через `set_content`/`add_script_tag`, не делает HTTP-запросов и не зависит от Cosmic. Снимки сохраняются в `screenshots/` (создаются при тестировании; не являются частью runtime).

Проверяются три варианта, работа счётчика и фильтра, 5 видов событий, подробности, пустое состояние, 40 строк и скролл, перемещение и resizing, закрытие/открытие, несколько разрешений от **320 до 1440 px**, отсутствие JS-ошибок и сетевых запросов.

## Известные границы

Это **только выбор внешнего вида**, поэтому операции в браузере изменяют `state.items` и не записываются на сервер и в `localStorage`. Отображаемые строки и относительные отметки времени вымышленные. В будущем нельзя напрямую переносить тестовые данные, мини-менеджер перемещения, настройки демонстрационной сцены или логику авторизации.

**Ветка и PR не должны сливаться в `main` до явного утверждения владельцем.**
