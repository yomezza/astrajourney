# Рабочие пространства космического терминала

Cosmic хранит одну раскладку Studio на аккаунт. На первом чтении создаётся пустое пространство «Астра». В дальнейшем запуск терминала восстанавливает последнее выбранное пространство. Команда «Открыть стартовое» переключает на пространство, выбранное игроком как стартовое. Текущие локальные настройки старых окон доступны по прежним ключам. При добавлении нового окна Studio может взять начальную геометрию соответствующего старого окна.

В Studio доступны отдельные окна просмотра корабля, трюма и добычи. У окон есть собственные UUID, расположение и привязка. Настройки хранятся отдельно от активного игрового корабля. Игровые команды остаются в существующих окнах. Chat, Notifications и карта открываются через свою обычную навигацию. Chat и Notifications используют прежние компоненты и общую для аккаунта связь.

## API Cosmic

- `GET /api/workspaces` возвращает `{revision, layout}` авторизованного аккаунта.
- `POST /api/workspaces` принимает ту же структуру с последней полученной `revision` и полной новой раскладкой. Операции создания, дублирования, удаления, перестановки, назначения стартового, выбора активного пространства и настройки окон записываются атомарно.
- `layout` содержит `version: 1`, UUID `active` и `default`, а также упорядоченный массив `workspaces`. Каждое пространство содержит `id`, `name`, `ship_id` и массив `modules`.
- Дескриптор модуля содержит `id`, `type` (`fleet`, `cargo`, `mining`), `binding` (`workspace`, `fixed`, `none`) и `ship_id`. Значение 0 используется, если фиксированного корабля нет. Допустимы `geometry` с `x/y/w/h/pinned/minimized` и `filter` для сортировки трюма (`name`, `quantity`).
- Сервер проверяет доступ к вновь привязанным кораблям. Сохранённая ссылка на недоступный корабль остаётся видна в интерфейсе, где пилот может выбрать другой.
- Лимиты составляют 1–10 пространств, 1–32 графемы имени, до 16 окон в пространстве и 64 КиБ на запись. Для невалидного документа или корабля возвращается 400, для чужого UUID — 422, для устаревшей ревизии — 409. Повтор той же записи сразу после успешного сохранения возвращает текущую ревизию без второй записи.

## PostgreSQL

Идемпотентная startup-миграция Cosmic добавляет в предметную схему identity таблицы `pilot_workspace_preferences` (FK к `users`, ревизия и JSONB) и `pilot_workspace_ids` (уникальные UUID и владелец, каскад через родительскую запись). Игровые таблицы и их строки не изменяются. Обновление документа и реестра UUID выполняется в одной транзакции. Для проверки используйте одноразовую PostgreSQL с именем БД, заканчивающимся на `_test`.

```sh
go test ./internal/server/integration -run '^TestWorkspacePreferences$' -count=1
cd tests/ui
node --test workspaces.test.mjs
```
