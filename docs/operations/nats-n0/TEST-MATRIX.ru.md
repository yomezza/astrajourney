# Матрица и воспроизведение N0

`Test-NatsN0Acl.ps1` отправляет fixtures в настоящие имена signals, поэтому
жёстко разрешает только loopback и отдельный непривилегированный порт,
не 4222. **Не запускать эти проверки на рабочем NATS**, даже если он временно
слушает другой порт. По умолчанию используйте контроллер ниже, который сам
создаёт отдельный процесс и приватное временное хранилище.
Перед отправкой fixtures пробник также требует server_name `N0-isolated-only`.
Это дополнительная защита от случайного выбора основного cosmoNATS.

## Матрица

| Проверка | Ожидается | Где выполняется |
| --- | --- | --- |
| TLS CONNECT каждого из 3 login с его password file | принят | локальный стенд; отдельно read-only login на Windows после согласования TLS |
| CONNECT без user/password | отказ auth | изолированный стенд |
| Каждый из 14 разрешённых publish subjects | принят | изолированный стенд |
| Каждый из 14 разрешённых subscribe subjects по ролям | принят | изолированный стенд |
| Publish в subject двух других producers | permission violation для каждого login | изолированный стенд |
| Publish `$JS.API.INFO`, `$SYS.REQ.SERVER.PING`, Economic event, unrelated | отказ для каждого login | изолированный стенд |
| Subscribe `>`, `cosmos.v1.signal.>`, `$JS.API.>`, `$SYS.>`, `_INBOX.>`, unrelated | отказ для каждого login | изолированный стенд |
| Planet sector signal → разрешённый Chat subscriber | получен ровно один fixture | изолированный стенд |
| Неизвестный CA | отказ TLS | изолированный стенд |
| Верный CA, но неправильный SAN/server name | отказ TLS | изолированный стенд |
| `/jsz`, лимиты | enabled, 512MB/10GB | изолированный стенд; Windows read-only отдельно |
| Файловый JS stream и сообщение → штатный restart → чтение | состояние сохранено | только временный store |
| Старый TCP после остановки, retry после старта | старое соединение закрыто, новое аутентифицировано | только дочерний тестовый процесс |
| Monitoring с постороннего ПК | TCP 8222 недоступен, локальный GET работает | **ручная Windows/LAN приёмка, не проверено из облака** |
| Служба/Firewall/backup рабочего сервера | inventory + проверенный restore | **Windows, пока не проверено** |

Точный перечень subjects — [acl-matrix.json](acl-matrix.json), полученный из
каталога 03. Тест использует его как ожидаемый контракт **отдельно** от server
ACL; фактическая проверка проводится NATS Server, а не сравнением строк шаблона.

## Автоматический изолированный запуск

Нужны Python 3.11+, пакет `bcrypt==5.0.0`, OpenSSL, PowerShell 7.4+ и официальный
`nats-server`. Установка инструментов — только на тестовой машине/в dev-папку,
без замены рабочего брокера. У опубликованных бинарников проверить SHA256SUMS.
На Windows запускайте через `pwsh`, не Windows PowerShell 5.1.

```powershell
$n0Venv = Join-Path $env:LOCALAPPDATA 'cosmosimulator-n0-tools'
python -m venv $n0Venv
& "$n0Venv\Scripts\python.exe" -m pip install bcrypt==5.0.0
& "$n0Venv\Scripts\python.exe" .\docs\operations\nats-n0\scripts\run_isolated.py `
  --nats-server 'D:\cosmosimulator\nats\nats-server.exe' --pwsh 'pwsh'
```

Для Linux замените Python из venv и пути на свои. При работе в среде с
ограниченной домашней папкой PowerShell можно направить XDG cache/config/data
в приватный dev-каталог. Сетевые proxy/CA не отключать для скачивания инструментов.

Контроллер выбирает свободные loopback-порты, создаёт свежую временную CA,
сертификат, случайные пароли, bcrypt и отдельный store. Он использует **копию
production-шаблона**, заменяя адреса/пути только внутри временной папки. В
test auth добавляет узкого `n0_test_operator` для единственного `N0_ISOLATED`
stream. Этого login нет в production-шаблоне и его нельзя переносить в рабочий
auth.config. Bcrypt cost 4 ускоряет только локальный тест; production — >=11.

PowerShell выполняет 71 ACL/TLS проверку, затем Python проверяет JS и
перезапуск/сохранность. Останавливается исключительно дочерний процесс,
созданный этим запуском; сторонние PID/SCM службы никогда не выбираются.
Временные ключи, пароли и test store удаляются после завершения, рабочее
хранилище недоступно через параметры контроллера. Для воспроизведения ошибок
не сохраняйте test secrets в Git.

## Что тест не доказывает

- Что реальные Windows Firewall, NTFS ACL и service account уже настроены.
- Что рабочий брокер имеет ту же версию и сертификаты.
- Что production backup восстанавливается или что данные переживут power loss.
- Что будущий Go NATS-клиент автоматически переподписывается: пока проверен
  только retry/новая auth-сессия изолированного пробника.
- Что игры уже работают через NATS или измерен выигрыш DB/latency.
- Что все ACL пользователя игры проверяются NATS: они по-прежнему в PostgreSQL.

Условия подключения и восстановления реальных игровых clients остаются
задачей N1/N3 и пилотов. Ни одна из этих будущих гарантий не следует из N0.
