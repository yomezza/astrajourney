# Переименование в Astra Journey · 0.24.13

Название продукта — **Astra Journey**, технический префикс — **astra-journey**.
Адрес GitHub по решению владельца остаётся yomezza/cosmosimulator; соответствующий
Go module/import path сохранён, чтобы он совпадал с настоящим адресом исходников.

Изменены заголовок страницы, шапка/футер терминала, демонстрации интерфейса,
логи запуска, названия актуальных команд, файлов сборок, новых SCM-служб,
release workflow/build script, текущие инструкции и шаблоны. Версии всех служб
и отображаемая версия терминала — 0.24.13. Игровые правила/права не менялись.

| Служба | Каталог команды | Префикс бинарника | Новое имя SCM |
| --- | --- | --- | --- |
| Cosmic | cmd/astra-journey | astra-journey | AstraJourney |
| Planet | cmd/astra-journey-planet | astra-journey-planet | AstraJourneyPlanet |

не переименовывались. Новые Windows/Linux файлы используют новый префикс.

## Существующая установка

Сохранить рабочий CONFIG_FILE и его значения database.schema, пути к логам,
данным и erasure_journal. **Не менять схему БД с cosmosimulator на astra_journey
ради названия:** это разные схемы, и новая будет выглядеть как пустой мир.
Примеры с astra_journey предназначены для новой установки; прежняя схема
поддерживается без переименования. Сам PostgreSQL и существующие каталоги
владельца из облака не изменялись.

Поля `[cosmos]`, `[planet]`, `[chat]`, NATS-профили/логины cosmos/planet/chat,
subjects cosmos.v1.*, HTTP/WS маршруты и ключи браузерных настроек сохранены:
это совместимые технические контракты, а не название продукта. Старые значения
migration marker распознаются, чтобы rename не перестраивал fuel constraint.
Planet health теперь указывает astra-journey-planet; Cosmic принимает и прежний
идентификатор Planet при последовательном обновлении служб.

SCM записи и unit-файлы ОС сами не переименовываются от замены EXE. Обновить
binPath/ExecStart при смене пути к бинарнику; при регистрации новых Windows
служб использовать имена из таблицы, сначала остановив прежние процессы.
Не запускать одновременно старую и новую Planet на одной схеме. Native Windows
SCM здесь не проверялся; Windows amd64 cross-build выполнен. Для Linux службы
остаются обычными Go-процессами с SIGTERM и могут запускаться через systemd.

Проверки: compile/unit `go test ./...` — PASS; native `-race` запуск трёх
новых команд с общим TOML/PostgreSQL/NATS и восстановлением брокера — PASS;
проверки demo registry и исследований — PASS (13 сценариев). Собраны все шесть
Windows/Linux amd64 файлов, PE/ELF и SHA256 проверены build script. Обширные
нагрузочные проверки для переименования не запускались.
