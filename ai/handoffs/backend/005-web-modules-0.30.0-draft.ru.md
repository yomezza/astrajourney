# Черновик 0.30.0: загрузка модулей и пятая служба Web

## Статус и границы

Ветка `feature/web-module-experience`, база `849933ffb7d704239129a1be7a3f454527668923` (`origin/main`, опубликованная линия 0.29.0). Изменения подготовлены локально, без push, PR, тега или публикации. Владелец прямо запретил публикацию нового черновика; для будущего выпуска нужна новая команда. Рабочая PostgreSQL владельца не использовалась: все проверки выполнялись на локальных базах `*_test`.

После подготовки черновика владелец новой командой «Давай релизни в репозиторий» разрешил публикацию и уточнил: «делай сборки только под линукс». Предыдущий запрет относится к этапу черновика. Разрешена публикация исходников, пяти Linux amd64 бинарников и пакетов; рабочая БД и действующие службы не меняются.

Предыдущие изменения 0.28/0.29 повторно не внедрялись. Выполнена новая задача: общий загрузчик окон, планировщик, отдельная панель администратора, удаление «Верфей» из навигации, основатели 03/04, перенос фронтенда и шлюза в Web.

## Реализация

- Клиент перенесён из `internal/server/web/` в `web/`. Cosmic встраивает только SQL и обслуживает API; CDN больше не пересылает остальные маршруты в Cosmic. Все пять исходных версий — `0.30.0`, это номер **неопубликованного** следующего выпуска.
- `web/ui/module-loading.js` и `ui/windows.js`: внутренняя загрузка по умолчанию для окон, недоступный до готовности контент, ожидание обещаний, eager-изображений и SVG-голограмм; ограничение ожидания, повтор и отмена. Для нового модуля обязательная асинхронная работа должна возвращаться через `Modules.prepare`, `Modules.load` или `Modules.wait`. Поверхность дополнительно ждёт подготовки Canvas/текстур. Вложенные исследования и окна колонизации используют ту же границу готовности. Проверки сессии и области администратора сохранены.
- Планировщик: сводка running/queued/paused, фильтр очереди, новый блок создания задачи и карточки кораблей. Команды продолжают выполняться существующим авторизованным API. Панель администратора — окно с четырьмя категориями и переходами к специализированным модулям.
- Кнопка «Верфи» убрана из боковой панели; вкладка рынка и покупка кораблей сохранены. `schema300.sql` добавляет основателей 03/04 с защитой занятых игроками имён/тегов. Старые ID и территории не перераспределяются. Новая генерация использует четыре основателя; пустые галактики остаются пустыми. Версия в `game_release` обновляется один раз, последующие операторские изменения переживают рестарт.
- `cmd/astra-journey-web`, `internal/webserver`: HTTP-шлюз и WebSocket-проксирование, сохранение cookie/Origin, удаление внешнего служебного токена и недоверенных forwarding-заголовков. Непубличные внутренние маршруты блокируются. Cache-Control CDN сохраняется; HTTP-дедлайны не переносятся на WebSocket.
- `internal/webbundle`, `cmd/astra-web-assets`: внешний пакет HTML/CSS/JS/JSON, SHA-256, ограниченные ZIP/пути/размеры, атомарный указатель активной ревизии и откат. HTML закрепляет `/web/<revision>/...`, файлы имеют immutable-кеш, локализации привязаны к той же ревизии. Синхронизация закреплена за опубликованным тегом и проверяет контракт API; `main` не скачивается.
- Web не подключается к SQL. При NATS использует отдельную identity `web`, только SUB двух сигналов CDN. Сигнал инвалидирует публичный asset-map; HTTP повторно читает его по запросу, TTL 30 секунд обеспечивает работу без NATS, reconnect тоже инвалидирует кеш. Кеш не содержит приватные медиа и не подтверждает доставку ресурсов браузеру.

## Запуск и совместимость

Основная инструкция: [docs/operations/web.ru.md](../../../docs/operations/web.ru.md). Есть отдельный и общий TOML, systemd unit и фрагмент ACL Web.

Внешний адрес остаётся Web `:8083`, CDN переводится на внутренний `:8084`. Сохранить прежние schema, CDN storage/token и журнал Chat; обновить upstream URL, public_origin и allowed_origins. Cosmic первым применяет новую миграцию. Web/CDN могут использовать отдельные TOML без `[database]` и без доступа Web к токену CDN.

До публикации `v0.30.0` автоматическое получение этого тега закономерно не найдёт пакеты. Для черновика использовать локальную установку обоих архивов и `sync_enabled=false`. `--install-pack` устанавливает пакет и завершается; затем процесс запускается обычной командой. Браузер открывает Web.

Локальные проверочные сборки находятся в игнорируемом `dist/review-final300/`: десять бинарников amd64 для Linux/Windows, пакеты графики и интерфейса, JSON-индексы, SHA256SUMS, `smoke-result.json`, четыре PNG в `previews/`. Сборки получены из рабочего дерева (`source_dirty=true`), а не из опубликованного тега. `downloads/`, старые SHA256SUMS и release-notes не менялись. Код упаковки/будущего release workflow обновлён, сам workflow не запускался.

## Подтверждённые проверки

Среда: Go 1.26.0, PostgreSQL 17.12, NATS Server 2.12.3, Node 24.22.1, Chromium 156.0.8078.79.

- `npm test` в `tests/ui`: **84 PASS**, включая пять новых сценариев готовности/повтора/отмены, вложенные исследования, SVG-голограммы, категории и потерю роли. Пройден осмотр desktop/390 px, переполнения планировщика нет.
- Все пакеты Go вне `internal/server/integration`: PASS. Новые пакеты Web/bundle, configuration, gamesignal и natscore проверены с `-race`; `go vet ./...` прошёл.
- Интеграционный набор охватывает **178 корневых тестов: 161 PASS, 17 опциональных SKIP**; имена проверены против списка скомпилированного тестового бинарника. Чувствительная к таймингу четверть перепроверена отдельно: при параллельных SQL-нагрузках локального хоста тест с искусственным DBTimeout=200ms получил дополнительный transient heartbeat error; отдельно все 45 тестов этой четверти прошли, включая 61 секунду соединения через Web. Тесты и игровая реализация ради этой ошибки не ослаблялись. Сводка — `dist/review-final300/test-results.json`.
- Реальные HTTP/браузер/PostgreSQL-сценарии через Web: каталог исследований/колоний, именование, редактор галактик, уведомления, терминал с покупкой корабля и командами планировщика, локальная сцена, строительство, клавиатурное управление, переходы и руководство. Отдельный сценарий прошёл 70 секунд ходьбы без переподключения.
- CDN-кеш: 7 первоначальных PNG-передач, 0 повторных после новой навигации, Canvas читается, голограмма загружается. Web не добавляет `no-store` поверх immutable-заголовка CDN.
- Нативный NATS Web: инвалидация каталога, работа при остановленном брокере по TTL, сброс после reconnect. Нативные N5/N6 проверены с настоящими отдельными процессами и `-race`.
- Реальные Linux-бинарники всех пяти служб запущены совместно: пять ready-карточек, вход и API через Web, версия из БД 0.30.0. Web и CDN запускались с TOML без `[database]`. Cosmic/CDN `/` возвращают 404, Web `/` — 200. Тестовые процессы остановлены, собственная smoke-БД удалена.
- `build-release.py v0.30.0 --platform both --out dist/review-final300`, `verify-web-release.py` и SHA256SUMS: PASS. Windows-бинарники собраны и проверены как PE amd64, их запуск на Windows здесь не проверялся.
- Linux Cosmic: 16 097 442 → 14 373 026 байт относительно опубликованной 0.29.0, уменьшение около 10,7%.

При расширенном прогоне обновлены старые тесты, предполагавшие UI/шлюз в Cosmic, чтобы проверять их через настоящий Web. В старом N5 test-only probe исправлена неинициализированная `buildGate`/`db`: это мешало тесту дойти до намеренного сбоя RAM join. Игровая реализация переходов не менялась.
