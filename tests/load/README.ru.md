# Смешанный нагрузочный прогон 0.30.0

Это отдельный эксперимент над опубликованными Linux amd64 бинарниками. Игровые
службы не собираются заново и не заменяются mock-серверами. Результат выполнения
тестового драйвера `PASS` означает завершение сценария; качество работы игры
оценивается по ошибкам, соединениям, задержкам и сверке данных в отчёте.

## Что требуется

- Linux с доступным `/proc`, Go 1.26, PostgreSQL 17 на `127.0.0.1` и отдельная
  начальная база с именем, заканчивающимся на `_test`. Локальный тестовый
  пользователь должен иметь право создать/удалить **новую временную БД** и роли.
- Опубликованные пять файлов `downloads/*v0.30.0-linux-amd64`, актуальные JSON
  индексы и ZIP графики/интерфейса из того же выпуска.
- Настоящий `nats-server` (проверялся 2.12.3). Fixture автоматически создаёт
  отдельный loopback-брокер с TLS, временными сертификатами и ACL для пяти служб.
- Node.js для одного браузерного участника, зависимости `tests/ui`
  (`npm ci --prefix tests/ui`) и Chromium/Playwright. Node.js используется только
  тестами; для запуска игровых служб он не требуется.
- Достаточно свободного диска: подробные журналы пяти служб за полчаса могут
  занимать несколько гигабайт. Сборку, npm install и другие тяжёлые проверки
  нужно закончить **до** измерения нагрузки.

## Запуск

Задать `TEST_DATABASE_URL` локальной тестовой базы своим обычным способом,
не сохранять пароли в журнале или Git. Внешний адрес сервера драйвер не принимает.

```sh
export TEST_NATS_SERVER_BINARY=/path/to/nats-server
export CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium
# Только если окружению действительно нужен этот режим Chromium:
export CHROMIUM_NO_SANDBOX=1

# Короткая проверка стенда: 5 → 10 → 20 участников.
RUN_MIXED_100=1 MIXED100_USERS=20 MIXED100_RAMP=10s MIXED100_HOLD=35s \
  go test ./internal/server/integration -run '^TestMixedPlayers100$' \
  -count=1 -timeout=8m -v

# Основной сценарий: 25 и 50 участников по минуте, 100 — 30 минут.
RUN_MIXED_100=1 go test ./internal/server/integration \
  -run '^TestMixedPlayers100$' -count=1 -timeout=45m -v
```

Без `RUN_MIXED_100=1` тест пропускается. Все HTTP-порты выделяются на loopback,
создаётся новая база `mixed100_<id>_test`, отдельная схема, роли, локальные
хранилища Web/CDN и конфигурация. Очистка останавливает только дочерние процессы
эксперимента и удаляет только созданную им БД. Начальная тестовая база остаётся.
При аварийном убийстве самого драйвера автоматическая очистка не гарантируется;
проверять оставшиеся ресурсы по ID конкретного прогона.

## Модель игроков

99 участников используют HTTP и WebSocket через настоящий Web, ещё один —
настоящий Chromium с опубликованным интерфейсом. Этот браузер входит в число
100, дополнительного игрового аккаунта наблюдателя нет.

- 30% высаживаются на сгенерированную планету: ходят по разрешённым клеткам,
  строят/удаляют объекты, пытаются переходить между соседними доступными секторами.
- 70% занимаются торговлей, складом, добычей, перелётами, исследованиями и
  перевозкой через планировщик. Команды учитывают полученное состояние корабля.
- Терминал повторяет семь запросов состояния примерно раз в пять секунд и
  обновляется после успешных команд. Незавершённые обновления не дублируются.
- Все подключены к Chat `b1`. Ровно 80% могут отправлять сообщение раз в 15–25
  секунд с индивидуальным смещением; это около четырёх сообщений в секунду,
  **не** 80 сообщений в секунду. Есть глобальный, корпоративный и пространственные
  каналы. Уведомление `sync` вызывает bootstrap/notifications/history с debounce.
- Первоначальные корабли, ресурсы, знания и корпоративные права подготовлены
  до измерения. Во время сценария SQL не телепортирует игроков и не ускоряет
  исследования/перелёты. PostgreSQL используется для наблюдения и финальной сверки.
- Все службы работают с `diagnostics.enabled=true`; у Planet сохранён также
  старый журнал. Пулы трёх игровых DB-служб ограничены восемью соединениями каждый.

Драйвер сохраняет неожиданные разрывы, а не скрывает их бесконечными повторами.
Завершение при >25% HTTP 5xx/transport после прогрева обозначается
`stopped_on_overload`. HTTP 4xx и игровые отказы анализируются отдельно:
`server_busy` нельзя считать успешным обслуживанием только потому, что нет 5xx.

## Артефакты

Каталог `dist/mixed100/<UTC run ID>/` не добавляется в Git:

- `report.json` — сценарий, SHA-256 бинарников, фазы, HTTP/WS метрики, финальная
  сверка пользователей, кораблей, задач, грузов и сообщений;
- `samples.jsonl` — каждые пять секунд CPU/RSS, пулы, SQL-счётчики, лаги, NATS,
  соединения PostgreSQL и объём журналов;
- `progress.json` — текущая фаза и живые соединения;
- `browser.json`, `previews/` — настоящая браузерная проба, открытия доступных
  модулей, ошибки и long tasks;
- `logs/` — структурированные и консольные журналы всех пяти служб и брокера.

`observe-mixed100.py` — дополнительный **read-only** наблюдатель за деревьями
процессов. Использован в первом прогоне из-за отсутствия `/proc/*/task/*/children`
в управляемом окружении. Драйвер после этого получил fallback через `stat.ppid`.
Для первого baseline CPU PostgreSQL/NATS/Chromium нужно брать из дополнительного
`process-trees.jsonl`, а не неполных групп в `samples.jsonl`.

Первая браузерная проба также имела ошибку навигации: профиль/уведомления вне
sidebar пропускались, а пункт карты внутри закрытого `details` не нажимался.
Её таймауты клика не являются задержками сервера. В `harness_version:2` поиск
кнопок расширен и меню раскрывается перед кликом. Цифры первого baseline
относятся к исходной пробе; успешны измерения рынка, задач и исследований.

```sh
python3 tests/load/observe-mixed100.py dist/mixed100/RUN_ID \
  --generator OWNED_TEST_PID --postgres LOCAL_POSTMASTER_PID
python3 tests/load/summarize-mixed100.py dist/mixed100/RUN_ID --plot
```

Сводка создаёт `summary.json` и при `--plot` экспорт SVG/PNG; для графика нужен
Matplotlib. Дополнительный всплеск публичной графики запускается только против
действующего собственного Web и не создаёт новых аккаунтов:

```sh
node tests/load/mixed100-assets.mjs http://127.0.0.1:OWNED_WEB_PORT \
  dist/mixed100/RUN_ID/asset-burst.json
```

Это 680 холодных загрузок выбранных SVG/PNG и 11 ETag-проверок. Самостоятельно
этот HTTP-тест не доказывает работу браузерного кеша, FPS или GPU-рендера.

## Как читать результат

CPU указан в ядрах: `1.0` — одно полностью занятое ядро. Нагрузка генератора,
Chromium и БД входит в общий cgroup и выделяется отдельно. Сумма RSS PostgreSQL
повторно считает общие страницы; она не равна физически занятой памяти.
`memory.current` включает файловый кеш растущих логов. SQL-счётчики — клиентские
вызовы pgx, а не количество внутренних операторов SQL-функций PostgreSQL.

Перцентили HTTP включают все ответы соответствующего endpoint; коды ответов
нужно читать рядом. `chat.send_to_first_history` — до первого обнаружения в
истории одним клиентом; это не задержка доставки каждому из 100 получателей.
Финальные соединения закрываются драйвером намеренно после десятисекундного
drain; отменённые при завершении запросы выделены отдельно.

Локальный результат на новой базе не определяет ёмкость сервера владельца:
важны его CPU/диск, размер мира и истории, задержки сети, дополнительные
галактики, состав действий и количество одновременно открытых браузеров.
