# STYLE GUIDE — Original C / «База знаний пилота»

**Назначение:** передать выбранную владельцем визуальную композицию разработчику для будущего переноса в production с сохранением настоящих `Modules`, данных и игровых действий. Дизайн — **первоначальный C** из первой пятёрки концепций, а не последующие B/C/D/E-производные. Демо содержит целевые исправления прокрутки и SVG.

## 3. Размеры, типографика, геометрия

- **Окно всегда прямоугольное:** `border-radius: 0`, тонкая рамка `1px`; стандарт демонстрации **810×550**, но production использует собственные сохранённые размеры и ограничения.
- **Titlebar** 34px и текст 11px, аналогично чату. В production titlebar **не создавать повторно**, оставить `Modules.header('guide')`.
- **UI-кнопки** минимальная высота **24–25px**, углы 0, фон `#192A35`, рамка `#405966`, hover `#263F4B`.
- **Основной UI-текст:** Segoe UI / system-ui 11px, межстрочный около 1.45; вторичные служебные метки — monospace 8–9px.
- **Заголовок статьи:** 21px обычное окно, 18px узкое (исключение ради иерархии статьи).
- Разделители `1px`, отдельные строки списка 49px с текстом 10px и аннотацией 9px.
- Прокрутка `scrollbar-width:thin`, цвет thumb `#496273`, фон `#16242E`; отдельные полосы списка и статьи.
- Поиск — на всю ширину с компактным `32px` полем в верхней панели, без крупной карточки.

Точные CSS-якоря: `.mode-c`, `.c-hero`, `.c-big-search`, `.c-tabs`, `.c-main`, `.c-index`, `.c-category-chips`, `.g-chip`, `.result-row`, `.c-reading`, `.article-pane`, `.holo-frame`. Это **не новая система рабочих пространств**; демо-обвязка находится вне указанной структуры.

В узком окне (примерно менее 595px) две колонки становятся **двумя вертикальными скроллируемыми зонами**: каталог сверху (~34% доступной высоты), статья снизу; доступность списка не исчезает. Пользовательский скролл и состояние выбранных тем сохраняются.

## 5. Визуальные состояния

- `Все темы / Избранное / Недавние`: плоские вкладки, активная — янтарная линия снизу (`2px`).
- Активная категория: прямоугольный маленький chip (`.g-chip.active`), янтарная рамка/текст; не pill.
- Активная строка: тёмная подложка `#203844` + `inset 2px` янтарный индикатор слева.
- Неактивный статус: холодный серо-голубой без светящегося halo.
- Пустой результат: текст на фоне списка, **без большой пустой карточки**.
- Раздел статьи: тонкая горизонтальная линия сверху; без выноса каждого абзаца в отдельную карточку.
- Статьи о космических объектах: одна компактная `.holo-frame` с SVG поверх тёмной подложки; подпись `360°`. Данные статей не меняют игровые объекты.

## 6. Вращение SVG и ограничения

`hologram.js` — **демонстрационный генератор новых векторных wireframe-проекций** десяти типов объектов. Он НЕ использует production-ассеты. Геометрия каждый кадр пересчитывается с углом `θ=(t / period mod 1)×2π`, т.е. **полный поворот 0 → 180 → 360°** вокруг вертикальной оси. Точка после 360° совпадает с начальной, модель не делает искусственный разворот/сброс на 180°. Никакой CSS `rotateZ()` плоской картинки. При `prefers-reduced-motion: reduce` анимация замирает, сохраняя читабельность.

В настоящем клиенте `objectHologram()` → `objectModel()` выбирают файл `object-*.svg` по игровому виду объекта. **Не заменять production SVG этим генератором без отдельного решения.** Для утверждённого визуального результата проверить и при необходимости исправить непрерывность оборота в собственных производственных ассетах, не меняя логику объектов.

## 7. Поддержка состояния и безошибочный скролл

Прежняя лаборатория пересоздавала DOM и сбрасывала `scrollTop`. Новая версия запоминает `scrollTop`/`scrollLeft` для `data-scroll-key="c-list"` и `"c-reader"`, затем восстанавливает их **после** обновления DOM. Параллельно сохраняет фокус по `data-focus-key` и `selectionStart`, применяя `focus({preventScroll:true})`. `window.scrollY` тоже не меняется.

В production по возможности обновлять DOM **точечно**, не пересоздавая весь список ради одной статьи; при полной перерисовке использовать ту же идею локального состояния scroll. Не применять грубое `scrollIntoView()` при выборе статьи или фильтра, если игрок сам его не запрашивал.

## 8. Чего не делать при внедрении

- Не копировать `.app-header`, `.workspace`, `.stage`, `.titlebar`, `.window-tools`, макетный drag/resize, тестовые чекбоксы.
- Не копировать демо-глобальные правила для `body`, `button`, `input` в общий CSS игры; ограничить стили `#window-guide` / `.guide-content`.
- Не заменять `Modules`, `UI`, `I18n`, `Session`, `FormState`, API контракт и game catalog локальным массивом статей.
- Не создавать новый API поиска, SQLite/индексатор, отдельное WebSocket-соединение или новую систему окон ради этой компоновки.
- Не копировать демонстрационные образовательные тексты поверх реального справочника без проверки владельца и backend-разработчика.

**Итог:** это утверждаемый визуальный эталон и ручной демо-тест. Не утверждение о готовой интеграции с серверной игрой.
