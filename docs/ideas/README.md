### Как читать статусы

- **Концепция / idea:** предложение, внедрение не разрешено автоматически.
- **Согласовано / approved:** принято как направление, не равно «разработано».
- **Прототип / mock:** результат можно посмотреть отдельно от реальных служб.
- **Частично внедрено / staged:** проверяй каждый этап и действующий runtime, не делай вывод по одному файлу.
- **Реализовано / implemented:** допустимо только при подтверждении текущим кодом/проверками и ссылкой на них.

Например, наличие `docs/ideas/chat-service/` не отменяет существования реального Chat; а наличие mock-новостей не означает реального API новостей.

## Как добавлять и развивать идеи

1. Создай `docs/ideas/<slug>/README.ru.md` с задачей, границами, статусом, связанными файлами и тем, что **не входит** в текущую работу.
2. Добавь строку в этот реестр, не перемещая чужие папки и не переименовывая уже опубликованные ссылки.
3. Для задания конкретному чату используй `ai/prompts/` со **ссылкой** на этот README, а не копией, которая позже расходится.
4. Для пробной реализации явно указывай mock/production, ветку и пути. Для перехода в production нужна отдельная команда владельца.
5. Если одна и та же идея получила позднюю реализацию, добавь ссылки на код, тесты, релиз и скорректируй статус **с датой**, сохранив историю.

**Не делаем глобальную перенумерацию идей:** часть существующих документов уже использует собственные `01`, `02` и т.д. в пределах темы. Сквозные номера `NNN` вводятся только для **новых заданий ИИ внутри роли**, отдельно от идей.
