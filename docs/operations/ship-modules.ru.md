# Корабельные модули · 0.31.0

Реализовано в Cosmic и Web. Planet, Chat и CDN остаются на 0.30.3.
Модули имеют класс C/B/A/S и размер: 5C занимает 5 единиц оснащения.
Установленные размеры суммируются и не могут превышать бюджет корпуса.
Неустановленный экземпляр занимает в трюме объём, равный своему размеру.

## Игра

«Рынок → Модули» показывает станции текущей галактики игрока. Ассортимент,
цена и остаток у каждой станции свои. Покупка доступна при стыковке с продавцом;
купленный экземпляр появляется в трюме. В «Корабль → Оборудование → Оснащение
корабля» карточку можно нажать или перетащить из трюма в соответствующий отсек.
Снятие выполняется нажатием установленной карточки или перетаскиванием в трюм.
Обычное окно трюма также принимает снятый модуль. Для оснащения нужна стыковка;
активные полёт, добыча, исследование, перевозка, планировщик и высадка блокируют
операцию. При переполнении трюма снятие отклоняется целиком.

В начальном каталоге 32 варианта:

| Семейство | Классы | Действие |
| --- | --- | --- |
| Универсальный, рудный, ледовый и газовый добытчики | C/B/A/S | Совместимость с ресурсом и прибавка к добыче |
| Грузовые расширители размеров 1/2/3/5/8 | Только C | +10 единиц трюма на единицу размера |
| Системный сканер | C/B/A/S | Сокращение интервала сканирования на 10/20/35/50% |
| Топливозаборник | C/A/S | Сбор 2/5/10 топлива вручную раз в 10 секунд в открытом космосе |
| Ускоритель перехода | C/B/A/S | Сокращение времени гиперперехода на 10/20/35/50% |

Длительности округляются вверх, минимум — секунда. Топливозаборник не работает
при стыковке и не переполняет бак. Ускоритель не меняет расход топлива.
Добытчики разных подтипов могут стоять одновременно; для ресурса выбирается
лучший совместимый, их производительность не суммируется. Один сканер,
ускоритель, топливозаборник и один добытчик каждого подтипа на корабль.
Грузовых расширителей может быть несколько в пределах бюджета.

Базовое оснащение — бесплатный расширитель 1C и прежний тип добытчика:
B у добывающих корпусов, C у остальных. На новых кораблях обычный добытчик.
Трюм существующих кораблей после миграции сохраняет вместимость и груз:
10 единиц базового объёма становятся эффектом стартового расширителя.
Добытчик B даёт дополнительную единицу добычи. Снятые стартовые модули
можно продать за 0; повторный запуск не выдаёт их заново.
Покупной модуль продаётся за половину фактически уплаченной цены.

## Хранение и настройка

При корневой схеме `game` используются:

- `game_fleet.ship_module_catalog` — каталог: `id`, `name`, `kind`, `rating`,
  `size`, `price`, `effects JSONB`, `description`, `enabled`.
- `game_fleet.ship_module_hulls` — `class`, общий бюджет `capacity`, стартовый
  класс добытчика `mining_rating`. Исходный бюджет зависит от цены корпуса:
  `min(80, 8 + floor(price/50000))`. Администратор может изменить его в БД.
- `game_fleet.ship_modules` — отдельные принадлежащие кораблю экземпляры,
  `ship_id`, `catalog_id`, снимок характеристик `definition JSONB`, `installed`,
  фактически уплаченная `purchased_price`. FK и уникальный частичный индекс
  защищают принадлежность и одиночные отсеки.
- `game_economy.station_module_stock` — `star`, `station`, `catalog_id`,
  `quantity`, `price`, `enabled`; уникальный ключ станции и каталожной позиции.

Для другой корневой схемы префикс меняется автоматически. Все операции идут
в транзакции с проверкой владельца, доступности корабля, денег и вместимости.
Установку не храним одним изменяемым JSONB массива в строке корабля:
экземпляры сохраняют собственные ID и могут находиться в трюме или в оснащении.
Изменение каталога влияет на будущие покупки; купленный экземпляр сохраняет
снимок. Баланс существующих экземпляров нужно менять отдельной осознанной
миграцией, а не случайным редактированием шаблона.

Новые варианты существующих семейств добавляются строками в каталог без
пересборки. `effects`: `extractor` (universal/ore/ice/gas), `yield_bonus`,
`cargo_bonus`, `scan_percent`, `jump_percent`, `scoop_rate`; используйте только
поля соответствующего семейства. Новая механика/новое семейство требует кода.
UI локализует известные названия, произвольные новые названия показывает как
в каталоге. Отдельного административного редактора каталога пока нет.

При первом просмотре станции создаётся начальный ассортимент: C везде,
B примерно на половине станций, A на трети, S на седьмой части; выбор устойчив
для пары станция/позиция. Количество 8/4/2/1. Начальные цены берутся из каталога.
Новые варианты подхватываются так же. Изменённые остатки/цены не перезаписываются.
Автоматического пополнения нет: оператор задаёт нужные `quantity`, `price`,
`enabled` в `station_module_stock`. Для запрета позиции оставьте строку с
`enabled=false`: удаление строки допускает её повторное начальное создание.
Для снятия шаблона с продажи используйте `ship_module_catalog.enabled=false`,
а не DELETE — на каталог ссылаются существующие экземпляры.

Модули пока не перемещаются через обычную ресурсную логистику в склад или
между кораблями. Доступны покупка, перевозка в собственном трюме, установка,
снятие и продажа. Характеристики учитываются в ручной добыче и планировщике,
торговле, резервировании вместимости и расчёте времени исследования/переходов.

## Обновление

Сделайте согласованную резервную копию БД. Остановите Cosmic и другие процессы,
пишущие в игровую БД на время миграции. Первым запустите Cosmic 0.31.0:
он применит `schema310.sql`, выдаст оснащение существующим кораблям и обновит
общую версию в БД. Затем верните остальные процессы и запустите Web 0.31.0
с `[web] release_tag='v0.31.0'` и `sync_enabled=true` либо установите Web ZIP
вручную по общей инструкции. Старый Web не поддерживает новое оснащение.
Planet/Chat/CDN обновлять не требуется; новый пак графики не нужен.

Оболочка терминала возвращена к виду до 0.30.5. Новое оформление двух карт
сохранено. Выпуск частичный, общий GitHub Latest остаётся на полном 0.30.3,
поэтому для Web используйте явный тег. Самопроизвольный откат Cosmic на старую
версию после миграции недопустим: старый код не учитывает объём и эффекты модулей.
Для полного отката нужна согласованная резервная копия и прежний Web-пакет.
