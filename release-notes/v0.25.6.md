# Astra Journey 0.25.6 — сохранение Planet runtime при временной ошибке продления аренды

- Воспроизведён и исправлен дефект: после временной ошибки PostgreSQL координатор терял собственный fence и при восстановлении увеличивал его, отсекая уже работающие визиты того же процесса.
- При неподтверждённой потере связи сохраняется идентификатор аренды для условного продления. Срок аренды, проверка владельца/fence, авторизация и таймауты не ослаблены. Подтверждённые истечение и смена владельца по-прежнему отсекают старый runtime.
- Добавлены этап ошибки в WS/браузерной диагностике, отдельный код runtime_fence_lost и контекст серверных проверок. Повторяющиеся ошибки подготовки перехода журналируются с исходной причиной.
- Проверено на отдельной PostgreSQL: отказ до исправления (fence 1 → 2), восстановление без смены fence после исправления, соединение через Cosmic-прокси дольше минуты с блокировкой БД, resume/epoch/cleanup старого контроллера, возврат, logout, отзыв прав, второй игрок и настоящий takeover runtime. Пройдены адресные Go и три frontend liveness проверки; полный набор и production deployment не выполнялись.

Обновить Cosmic и Planet: только Linux amd64. Chat остаётся 0.25.2; миграций и изменений конфигурации нет. Перезагрузите страницу после замены служб. Ошибка из рабочего лога сама по себе не устанавливает единственную причину; для сопоставления сохранены точные этапы и серверный error. Опубликованные бинарники обратно не скачиваются.
