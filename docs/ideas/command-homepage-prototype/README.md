# Astra Journey — пять дизайнов главной страницы терминала

**Статус:** полностью автономный frontend-прототип; `internal/server/web/` не менялся, в production ничего не интегрировано.

## Запуск

Распакуйте архив и откройте **`index.html` двойным щелчком** в современном браузере. Файлы `styles.css`, `fixtures.js`, `app.js` подключены локальными относительными путями, ES-модули, CDN и сетевые API не используются. Нужны только HTML/CSS/JavaScript; нет зависимостей от Go, PostgreSQL, NATS, Cosmic, Planet или Chat.

Если политика браузера ограничивает загрузку локальных ресурсов, можно запустить простейший статический сервер:

```bash
cd command-homepage-prototype
python3 -m http.server 8767 --bind 127.0.0.1
# затем http://127.0.0.1:8767/
```

## Как пользоваться

Сверху есть переключатель **A / B / C / D / E**. Он изменяет только композицию, сохраняя одинаковые mock-данные. Нажмите **«0», «1», «3»**, чтобы сравнить пустой терминал, с одним или тремя открытыми окнами; состояния работают в любом варианте. Нажимайте элементы быстрого запуска или кнопки в боковой панели, чтобы открывать окна. За заголовок окно можно передвинуть, за нижний правый угол — изменить размер; работают закрытие, сворачивание, закрепление и перемещение стрелками клавиатуры после фокусировки заголовка. Повторное нажатие открытого модуля переводит окно на передний план.

**«Обновить данные»** локально меняет кредиты, XP, текущую звёздную систему, дату и отметку обновления. **«Повысить стаж»** выполняет только демонстрационное списание mock-кредитов при достижении порога XP. Все значения — вымышленные, без серверных запросов.

## Сравнение пяти концепций

| Подход | Композиция и характер | Преимущества | Компромиссы |
| --- | --- | --- | --- |
| **A · Mission Control** | Широкий блок идентификации, отдельная эмблема сети, три телеметрических блока подряд, двухколоночный командный стол | Самая понятная и сбалансированная иерархия; близок к существующему стилю; не требует новых данных | Чуть плотнее B; декоративная эмблема не несёт действия |
| **B · Minimal Command Dashboard** | Крупное имя в заголовке, тройка метрик одной полосой, спокойная сетка действий, почти нет дополнительных блоков | Максимум практичности и свободного пространства для окон; хорошо масштабируется | Меньше «личного командного мостика», скромная атмосферность |
| **C · EDEN Personal Workspace** | Большая личная карточка слева; правая панель с приветствием, тремя компактными метриками и действиями | Сильная индивидуальность пилота и Академии; необычная композиция | Большая карточка профиля занимает полезную площадь; на узких экранах складывается вертикально |
| **D · Holographic Command Interface** | Техническая круговая проекция по центру, баланс слева, местоположение и дата справа, короткая линия идентификации | Наиболее атмосферный вариант, подходит стилю научной фантастики | Проекция декоративна; занимает место; для небольшой высоты возможно больше прокрутки |
| **E · Modular Command Deck** | Панель модулей слева, список открытых окон в центре, показатели вертикально справа | Сильнее всего показывает принцип работы с модулями и несколькими окнами | Несколько плотный и похож на дополнительные панели управления; список окон демонстрационный, не новая механика |

**Предварительная рекомендация: A · Mission Control.** Он делает центральную область полезной и выразительной, не отнимая у трёх привычных инфоблоков их характер. Вариант B — практичная альтернатива, если требуется ещё меньше визуальной нагрузки. Окончательный выбор остаётся за владельцем.

## Проверки

При наличии `playwright` и Chromium:

```bash
CHROMIUM_PATH=/usr/bin/chromium python3 test_prototype.py
```

Проверяет все пять компоновок, одинаковый набор данных и три телеметрических блока, 0/1/3 окна, фокус и повторное открытие, pin/minimize/close, перемещение клавиатурой, повышение стажа, обновление данных, отсутствие JS-ошибок и внешних запросов, шесть размеров экрана (1920×1080, 1440×900, 1366×768, 1280×720, 390×844, 320×650). В изолированной тестовой среде `file://` и `localhost` навигация Chromium блокируются административной политикой, поэтому тест загружает **точное содержимое** локальных HTML/CSS/JS через `set_content`, `add_style_tag` и `add_script_tag`. Это не проверка запуска по `file://` в конечном браузере; все зависимости имеют относительные пути и не требуют HTTP.

## Границы демо

Это архитектурный и визуальный образец, а не production-клиент: окна созданы упрощённым локальным JS, операции с ресурсами и повышением уровня не воздействуют на сервер, пользователь фиктивный, часть production-меню и возможность доковать чат не воспроизведены, настоящих сетевых соединений нет. Не выдавать mock за реальную игровую бизнес-логику. Все различия и правила будущего переноса перечислены в `FUNCTIONALITY.md` и `HANDOFF.md`.

**Изменения production запрещены до отдельного утверждения дизайна.**
