# N0 — фактически проведённые проверки

Дата: 2026-11-09 (Екатеринбург, UTC+5). Это результаты отдельного **Linux**
стенда в облачной среде разработчика. Рабочий NATS владельца не подключался,
его версия, данные, Windows Services и Firewall не изменялись и не проверены.

## Инструменты

- Официальная сборка NATS Server **v2.15.2**, linux-amd64; архив сверён с
  `SHA256SUMS` того же GitHub release.
- Официальный PowerShell **7.5.4**, Linux x64; архив сверён с `hashes.sha256`
  соответствующего release. PowerShell выполнял настоящие `.ps1`/`.psm1`,
  не Python-имитацию ACL-проверок.
- Python 3.12, `bcrypt==5.0.0` в отдельном dev-venv, OpenSSL для временной CA.
- Версии зависимостей игровых Go-служб не менялись. Попытка dev-сборки внешнего
  nats-server через Go proxy встретила запрет скачивания зависимости; для теста
  использована официальная готовая сборка, без изменения сетевой политики.

## Прошло на изолированном экземпляре

1. Синтаксический разбор всех подготовленных PowerShell scripts/module.
2. `nats-server -t` для копии предлагаемого server/auth config с реальными
   **случайными тестовыми** bcrypt hash, TLS-файлами и отдельным store.
3. **71 успешная ACL/TLS проверка**: три положительных логина, отказ без
   credentials, все 14 publish и 14 subscribe allow entries, запреты чужих
   доменов, Economic/unrelated subjects, `$JS.API`, `$SYS`, `_INBOX`, wildcard
   подписок, отказ чужого CA и неверного имени сервера, реальная доставка
   Planet sector fixture подписчику Chat.
4. `/jsz`: JetStream включён, `max_memory=536870912`,
   `max_storage=10737418240` (512MB и 10GB).
5. В отдельном файловом stream `N0_ISOLATED` сохранён один fixture; после
   штатной остановки и запуска того же **тестового** брокера stream содержит
   одно сообщение с прежним sequence и содержимым.
6. Старое TCP-соединение закрывается после остановки; retry-пробник после
   запуска заново подключается с проверенным TLS и аутентификацией.
7. Все test resources — свободные loopback-порты и приватная временная папка.
   Контроллер останавливает только созданный им child PID. После теста store,
   private keys и пароли удаляются. Никаких streams рабочего брокера не создано.

Финальные строки воспроизводимого прогона:

```text

PASS JetStream enabled; configured limits 512MB/10GB
PASS reauthenticated reconnect after isolated restart; stored message survives
PASS test-only lifecycle; production ports and storage never selected
Server tested: nats-server: v2.15.2
```

## Не проверено и не считается пройденным

| Проверка | Почему пока нет результата |
| --- | --- |
| Версия и запуск рабочего cosmoNATS | Нет доступа к Windows хосту; не угадывается по dev-версии |
| Действующий auth.config, реальные логины/секреты | Не читались и не передавались |
| Подключение к 192.168.111.44:4222/8222 | У среды не настроен VPN к LAN, фактических соединений нет |
| Реальная загрузка нового TLS/ACL | Это только draft; применение не разрешено |
| Monitoring недоступен посторонним | Нужна проба с другого LAN-компьютера после согласованного переноса |
| Windows Firewall/NTFS/service account | Подготовлены inventory/ACL commands, Windows-ветки скриптов на Linux не выполнялись |
| Сохранность рабочего JetStream/backup/restore | Ни restart, ни чтение рабочих сообщений, ни backup/restore не выполнялись |
| Перезапуск после аварийного power loss | Проверен только штатный restart временного стенда |
| Автоматическое resubscribe/DB reconcile будущего Go client | Клиент пока не реализован, относится к следующему этапу |
| Поведение игры при потере NATS, производительность/бенчмарки | NATS не интегрирован в игру; пилоты не запускались |

## Итог готовности

Шаблоны и изолированная проверка N0 подготовлены. Продакшен-готовность не
подтверждена, пока оператор не выполнит Windows inventory и не согласует
применение/backup/TLS/ACL. Для следующего N1 требуется отдельная команда
владельца; автоматически к коду или пилотам работа не переходит.
