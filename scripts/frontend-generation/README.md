# Cosmosimulator: среда для работы над интерфейсом

Здесь хранится отдельная демоверсия веб-интерфейса Cosmosimulator. Она нужна, чтобы менять окна, расположение элементов и общие компоненты, не вмешиваясь в рабочий Go-сервер и базу игры.

Оригинал: [yomezza/cosmosimulator](https://github.com/yomezza/cosmosimulator). Базовая версия интерфейса — релиз `v0.23.0`, коммит `31e849aa600bfd272d5b1f2f3a0adddcb00f3133`. Для остальных игровых модулей берутся оригинальные HTML, CSS и JavaScript из `internal/server/web`. Ответы API подменяются вымышленными данными.

## Над чем работаем

Я выступаю frontend-разработчиком и помощником по аудиту UI. Моя задача — разбирать существующую реализацию, воспроизводить её поведение в независимой среде, вносить согласованные изменения и проверять их в браузере. Не меняю архитектуру игры, Go-обработчики и рабочий интерфейс по собственной инициативе.

У двух модулей уже есть согласованные отступления от оригинала:

- **Чат v13.** Разработан в отдельной демоверсии. В основной среде у него одна собственная плавающая панель без дополнительного окна `Modules` и без вложенной главной страницы. В режиме «На главную» тот же chat-root переносится под показатели пилота. Закрепление на главной перемещает тот же chat-root под показатели пилота; сохраняются компактные контекстные меню, эмодзи, список игроков, настройки и прототип модерации. Источник: `prototype/chat/`, резервная копия `prototype/approved-chat-v13.html`.
- **Исследования v13.** Система активного корабля идёт первой и отмечена в каталоге. Остальные системы можно выбирать для просмотра без перемещения корабля. Поле поиска прямоугольное, фильтр «Источник» использует ККМ, голограммы O/B/A/F/G/K/M подлинные и вращаются. Исходники: `prototype/studies/`, резервная копия `prototype/approved-studies-v13-offline.html`.

Прочие окна не перерисовываются: сохранены исходные `Modules`, `UI.menu`, `UI.picker`, `UI.hologram`, стили `tokens.css` и `terminal.css`. Перед переносом очередного изменения нужно отличать общую компонентную правку от правки конкретного окна.

## Запуск

Понадобится Python 3.10+ (для Windows рекомендуется 3.13) и браузер. Устанавливать Go, PostgreSQL и npm не нужно.

В каталоге `scripts/frontend-generation/`:

```bash
python launch.py
```

На Windows можно открыть `start.bat`, на Linux/macOS — `./start.sh`. После запуска: <http://127.0.0.1:8765/>. Корабли и остальные объекты можно проверить отдельно по адресу <http://127.0.0.1:8765/demo/assets/>.

В первом запуске происходят три операции: `update.py` проверяет новые версии программы в репозитории; `prepare.py` проверяет оригинальные ресурсы и при отсутствии скачивает их из GitHub (или копирует из локальной копии репозитория); `server.py` открывает локальную демоверсию. Повторно скачивать 152 файла оригинального frontend не требуется, если проверка прошла.

Для запуска без обращения к GitHub:

```bash
python launch.py --offline
```

Для отдельной проверки обновлений, без установки:

```bash
python update.py --check
```

Чтобы принудительно проверить и установить опубликованный код:

```bash
python update.py
```

Чтобы вручную переустановить исходные web-ресурсы с уже скачанного репозитория:

```bash
python prepare.py --from ../../
```

Для установки исходников из архива релиза используется `python prepare.py --archive имя.zip`. `prepare.py` печатает прогресс скачивания по байтам и распаковки/копирования по числу файлов. Если GitHub недоступен, локальная версия продолжает работать в пределах уже установленных ресурсов.

## Обновление программы

`update.py` обращается к GitHub REST API, определяет актуальный коммит ветки `main` и проверяет каталог `scripts/frontend-generation/`. Файлы скачиваются из **этого конкретного коммита**. Каждый файл проверяется по размеру и Git blob SHA до применения. Сначала собираются и проверяются все изменения, затем заменяются локальные копии. Заменённые файлы сохраняются в `.mirror-backup/`. Отдельная `.mirror-update-state.json` показывает последний установленный коммит.

Обновлятор работает с исходниками самой демоверсии, но **не** обновляет `original-web/`, загруженные изображения, пользовательские данные и файлы других каталогов репозитория. Для оригинального frontend используется отдельная команда `prepare.py`. Программу запускает пользователь; никаких фоновых задач и автоматических изменений на GitHub нет. Если локальный код был изменён вручную, его предыдущая версия попадает в `.mirror-backup/` — перед следующим запуском надо учитывать, что новая версия может изменить эти файлы.

У текущей версии загрузчик не выполняет обновления основного репозитория через `git pull` и не загружает исполняемые файлы из сторонних хостов. Он работает только с публичными исходными файлами заданного каталога в `yomezza/cosmosimulator`.

## Единый тестовый мир: карты, исследования и рынки

В `mock/registry.py` хранится **один** набор вымышленных звёзд (80 систем),
регионов, объектов, орбитальных станций, ресурсов и торговых предложений.
Идентификаторы объектов не меняются при открытии другого модуля. Пять
станций связаны с реальными объектами своих систем.

- **Галактическая карта** получает систему и гиперкоридоры из `/api/galaxy`.
  **Звёздная карта** открывает ту же систему через `/api/system?id=ID`,
  вместе с планетами, станциями и месторождениями; для неизученных систем
  объекты скрыты до сканирования.
- **Исследования v13** при открытии внутри общей демоверсии загружают
  `/api/demo/registry`, используя названия и классы этих же звёзд.
  Кнопка «На карте» переходит в настоящий модуль Galaxy, передавая
  выбранный ID. Отдельно открытый HTML по-прежнему использует свои
  автономные тестовые значения.
- **Локальный рынок** берёт `offers` из пристыкованной станции 1/104
  («Торговый маяк»), а **глобальный рынок** получает `ports` и
  `reservations` через `/api/market/global`.
  Демо-покупки, продажи, бронирование, получение и отмена меняют данные
  только в оперативной памяти Python. Новая сессия сервера восстанавливает
  исходные тестовые остатки. Оба рынка используют один запас каждой станции,
  а цены и ограничения отображаются штатными компонентами оригинального
  игрового frontend (без второго макета рынка).
- Игрок, корабли и данные экономики вымышленные; никаких игровых
  транзакций и изменений реальной базы нет.

Проверка контрактов и переходов — `python -m unittest discover -s tests -v`.
Тесты `test_registry_market.py` проверяют идентификаторы систем,
станции, цены и обновление запасов после бронирования.

## Версия программы и обновления

При запуске `start.bat` / `python launch.py` обновлятор сверяет программу с
`main`, скачивает отличающиеся файлы с проверкой Git blob SHA и записывает
`.mirror-update-state.json`. В консоли выводятся **полный установленный
коммит**, статус проверки и путь к каталогу программы. При ошибке загрузки
появится предупреждение; запуск из локальных файлов остаётся возможен.

Текущую запущенную версию можно проверить по адресу
<http://127.0.0.1:8765/demo/version> — в ответе указаны коммит, PID и каталог
сервера. Если порт занят старым процессом, программа сообщает об этом.
JavaScript и CSS демоверсии отправляются с запретом кеширования.

## Данные и ограничения

Все данные тестовые. Демоверсия не подключается к реальным Cosmic/Planet/Economic/Chat Service, не создаёт игроков и не обращается к PostgreSQL. Сервер слушает только `127.0.0.1`. Демоверсия предоставляет массивы проектов и возвратов для окна «Колонии»; проекты вымышленные. Уведомления хранятся в памяти, после удаления не восстанавливаются при обновлении страницы. Некоторые ответные структуры Go API воспроизведены не полностью; у соответствующих оригинальных модулей возможны пустые состояния или ошибки DTO. Раздел «Исследования» всё ещё использует отдельную прототипную разметку в оболочке, в отличие от уже нативно интегрированного чата.

Подтверждено локальными проверками: 33 SVG сопоставлены с Git blob SHA, консольная индикация скачивания работает, чат не дублирует главную, 23 модульных теста Python проходят. Полная браузерная проверка **всех** окон оригинальной игры с mock API пока не завершена; статус подробно записан в `AUDIT.ru.md`.

При обсуждении новой правки указываем конкретный модуль и элемент. Если изменение потребуется сразу в нескольких окнах, сначала проверяем, не используется ли там общий `UI`-компонент. Это убережёт от случайной замены рабочих стилей по всему приложению.
