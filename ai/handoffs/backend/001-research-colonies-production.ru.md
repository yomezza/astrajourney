# Исследования и колонии — интеграция в Cosmic 0.24.15

**Задание:** [утверждённый перенос двух модулей](../../prompts/backend/001-research-colonies-production/prompt.md).  
**Статус:** интерфейсы реализованы, проверки выполнены; сведения о публикации приведены ниже.  
**Рабочая ветка:** `feature/research-colonies-production`, основание — `main` на `1b9bac5`.  
**Объём:** только «Исследования», «Колонии», их интеграция, проверки и выпуск Cosmic. Изолированная демосреда не изменялась.

## Итоговый интерфейс

### Исследования

- Справа — каталог v13; нажатие на карточку или Enter/пробел выбирает систему.
- Слева меняются голограмма **выбранного** класса звезды, название, регион, источник сведений и доступные действия. Выбор не перемещает корабль.
- Текущая система корабля закреплена первой независимо от поиска, источника и страницы. Неисследованная текущая система не считается завершённым исследованием.
- Фильтр источника использует штатное компактное `UI.menu`, без поиска внутри меню; основной поиск прямоугольный.
- «На карте» передаёт исходный ID существующей галактической карте.
- «Подробнее» открывает реальные разрешённые сервером объекты. Исходные строковые ID (`planet-1`, `station`, `asteroids`) сохраняются. Звезда идёт первой, остальные объекты — в порядке орбит из DTO.
- Поиск, источник, страница и выбранная система сохраняются при возврате, обновлении снимка и смене языка. Закрытие окна снимает обработчики и удаляет tooltip.
- Перерисовка каталога и голограммы пропускается, если соответствующие данные не изменились. На странице до 10 строк, плюс закреплённая система корабля.

### Колонии

- Сохранён утверждённый двухколоночный каталог: крупная планета и сведения слева, поиск и карточки справа.
- Планета сопоставляется по числовым `star`/`planet`, без поиска по названию. Отсутствие раскрытого объекта показывает нейтральный SVG и сообщение о недоступности сведений.
- Смена исследовательских данных или ревизии мира обновляет метаданные; старый ответ не перезаписывает новый и не снимает маркер другого запроса.
- Асинхронное получение названия обновляет и каталог поиска. Выбор, поисковая строка и прокрутка сохраняются.
- «Открыть проект», поверхность, продолжение высадки и возвраты вызывают прежние production-функции. Финансирование, строительство, отмена и административное пополнение остаются в штатном окне проекта.
- Смена языка больше не открывает уже закрытую карту поверхности поверх другого модуля.

## Существующие API и права

Исследования используют `GET /api/galaxy`, сведения `known`/`research` из `/api/workbench`, текущую систему из `/api/expedition`, `GET /api/system?id=…`. Начало экспедиции сохраняет `Game.explore`: `/api/estimate?to=…`, подтверждение и штатную команду `/api/workbench`. Пауза/продолжение идут через тот же обработчик команд.

Колонии используют `/api/planet/projects`, `/api/system?id=…`, `/api/planet/project?id=…`, `/api/planet/surface`, `/api/planet/state`, `/api/planet/action`. Продолжение высадки использует существующий модуль `visit.js` и его прежний протокол.

**Новые игровые API, SQL-миграции, поля контрактов и серверные правила не добавлялись.** Производственный Go-код изменён только для номера версии. Изменения Go в тесте создают отдельную временную схему в БД с суффиксом `_test`; рабочая БД и действующие службы не использовались.

Источник раскрытия объектов — ответ сервера. Клиент не восстанавливает скрытые планеты из генератора, списка `star.planets` или mock-реестра.

## Проверки

Условия: Linux amd64, Go 1.27.3, PostgreSQL 17 в собственном тестовом контейнере, Chromium/Playwright. Тесты браузера используют настоящие Go HTTP-обработчики, собственные сессии и PostgreSQL; API не подменяются.

- `RUN_CATALOG_BROWSER=1 go test ./internal/server/integration -run '^TestCatalogProductionBrowser$' -count=1 -timeout=3m -v` — пройден: выбор системы/класс звезды, поиск/фильтр/страница/возврат, реальные ID и порядок объектов, SVG, tooltip/Escape, горизонтальная прокрутка, карта, проекты/взнос/поверхность/возврат, сохранение состояния, узкое окно, RU/EN, скрытые объекты, неизвестная планета, пустой каталог, запрет чужой операции.
- `RUN_PLANET_BROWSER=1 go test ./internal/server/integration -run '^Test(PartialSystemDiscovery|PlanetProjects120|PlanetConcurrencyPrivacy120|PlanetCorporateRightsAndRefunds120|PlanetBrowser180)$' -count=1 -timeout=3m -v` — все 5 пройдены: частичное исследование, строительство/возвраты, конкурентность/приватность, корпоративные права, настоящая высадка двух игроков с переподключением и возвратом.
- `node --test --test-concurrency=1 architecture.test.mjs terminal-flows.test.mjs` из `tests/ui` — 12 пройдены: граф ES-модулей и совместимость затронутых терминальных сценариев.
- `node --test tests/ui/catalogs.test.mjs` — пройден: поздние ответы разных ревизий, сохранение выбора/поиска, отсутствие восстановления данных после очистки.
- `go test ./...` без `TEST_DATABASE_URL` — пройден; интеграционные сценарии, требующие БД, в этом запуске пропущены. Реальные проверки БД перечислены отдельно выше.
- Проверены снимки экрана при ширине браузера 1440 и 600 пикселей; оконная адаптация использует размер контейнера. Ошибок JS и загрузки CSS/SVG в основном браузерном сценарии нет.

## Отличия от демосреды и ограничения

- Нет переключателя искусственных исследовательских состояний, iframe, Python API, вымышленных планет и mock-операций.
- В production сохранены исходные ID и проверки сервера; дополнительные изменения жизненного цикла устраняют конфликты с настоящим `Modules` и глобальной CSS-шапкой.
- Источник данных не расширен ради оформления. Например, список проектов не содержит `owner_user`/`owner_company`; каталог не угадывает тип владения по имени. Точные права остаются в полном окне проекта.
- Производственные файлы намеренно имеют перечисленные адаптации; прежнее demo-утверждение о побайтовом равенстве каталогов больше не является проверкой production. Содержимое `scripts/frontend-generation/` сохранено без изменений.
- Полный нагрузочный прогон и запуск Windows-приложения на Windows не выполнялись. Проверена браузерная функциональность; Windows amd64 собирается кросс-компиляцией. Чат не перерабатывался; общий ES-граф проверен.

## Публикация и продолжение

Задание явно разрешает публикацию в `main` после проверок; работа выполнялась в короткоживущей ветке с последующим согласованным этим заданием слиянием. В релиз входит только Cosmic для Windows/Linux amd64. Planet и Chat остаются `0.24.14`, конфигурация прежняя. Исторические файлы `downloads/` не удаляются.

Исходники интеграции: [`d843de5ebe9f8176c0bd7444c0e7e31f9997d724`](https://github.com/yomezza/cosmosimulator/commit/d843de5ebe9f8176c0bd7444c0e7e31f9997d724).
Сборки созданы из этого точного коммита (`source_dirty=false`), проверены форматы PE amd64/статический ELF amd64 и SHA-256; manifest — `downloads/astra-journey-v0.24.15-build.json`. Старые файлы и строки контрольных сумм сохранены. Подтверждение публикации добавляется после ответа GitHub. Следующий шаг — проверить оформление двух модулей на собственной установке; новые идеи терминала/новостей и другие прототипы в этот выпуск не переносились.
