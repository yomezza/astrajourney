# Жизненный цикл экземпляров

## Общий контракт
Реестр семейства задаёт допустимые purpose, binding, variants, placement, UI state schema, доступность, фабрику экземпляра. Общий контроллер: create → resolve context → load/mount → update → suspend/resume → destroy. Точные имена методов выбирает Frontend. Изолировать DOM, события, запросы, фильтры и черновики по instance UUID; не использовать глобальный root или singleton по type. Два одинаковых семейства могут одновременно управлять разными объектами.

## Плитки
Добавление через каталог сохраняет descriptor и geometry на аккаунте. Переключение пространства сохраняет UI preferences, скрывает/приостанавливает неактивные экземпляры, восстанавливает выбранные. Не повторять мутации при восстановлении. Удаление плитки не отменяет игровую задачу. Дублирование создаёт новые IDs и копирует допустимые настройки. Не восстанавливать устаревшие игровые данные как истину.

## Плавающие окна
Открываются через общий каталог/компактную навигацию в независимом контейнере; остаются открытыми и сохраняют исходную привязку при смене пространства. Не входят в сохранённую раскладку пространства, закрываются отдельно, не преобразуются в плитки и обратно. Поведение восстановления после F5/нового входа и предел окон пока не согласованы: по умолчанию временная сессия, уточнить до расширения. Закрытие окна очищает его ресурсы, не игровую операцию. Не клонировать чаты/уведомления.

## Состояния
loading, ready, empty, missing_context, unavailable/forbidden (не раскрывать приватный объект), error/retry, command_pending, stale. При потере соединения явно отмечать устаревшие данные, не обещать успешную команду до ответа сервера. Защита от двойной отправки; отмена запросов/игнорирование старых ответов при смене объекта. Команда захватывает конкретный target и параметры на момент подтверждения; сервер проверяет заново. При logout очистить приватные DOM, кэши, запросы и подписки. Не создавать polling/WS на каждый экземпляр: shared stores, дедупликация по объекту и ограничение частоты. Неактивные пространства не требуют постоянного рендера.
