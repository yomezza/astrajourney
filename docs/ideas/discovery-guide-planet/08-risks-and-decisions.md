# 08. Риски, варианты решения и вопросы владельцу

**Код Cosmic/Planet/Chat и Original C сверены на дату 13 ноября 2026.** Здесь сознательно отделены проверенные ограничения от предлагаемых правил, ещё требующих согласования.

## Технические риски

| Приоритет | Реальный риск | Меры |
|---|---|---|
| P0 | Первое историческое исследование не доказано временем surveys.received_at; источник получен покупкой | Legacy-unattributed; только будущие личные server actions могут claim; никаких случайных владельцев |
| P0 | Concurrent claim/rename, повтор HTTP | Условный SQL UPDATE с row lock, UUID history, одноразовый rename_used_at, тест rollback |
| P0 | Global names одновременно в galaxies JSON и metadata | Одна SQL tx World.Commit + world revision; authoritative registry; consistency audit |
| P0 | Корпорации-основатели защищены Star.Founder/companies.founder_key | Fail closed, проверять реальное соответствие; никогда не hardcode ID без осмотра |
| P0 | Старый Planet leave и Cosmic /api/planet/return позволяют уйти из любой точки | Серверный near-landing proof и проверка в ОБОИХ путях; совместный релиз |

## Предлагаемые продуктовые решения — подтвердить перед реализацией

1. **Первое открытие системы:** личное завершение исследования (а не первое посещение); **планета:** впервые раскрыта конкретная планета во время личного скана. Первый игрок системы и планеты могут отличаться. Рекомендую принять.
2. **Legacy:** уже исследованным объектам не присваивать первооткрывателя автоматически. Помечать legacy_unattributed, админ-подтверждение только по достоверной истории; новые ещё не исследованные доступны. Рекомендую принять.
3. **Founder:** все системы/планеты с действующей привязкой Star.Founder к компании-основателю защищены; вопрос смены границ founder territory после покупки/завоевания требует отдельной политики. Рекомендую защищать также при временном несовпадении записи до DBA reconciliation.
4. **Длина и символы:** системы/планеты 3–40 графем; колонии 3–60; NFKC+casefold+collapse whitespace; нежелательные и бессмысленные строки отсекать сервером. Рекомендую принять.
5. **Совпадение имён:** системы уникальны внутри galaxy, планеты внутри star, колонии внутри surface. Рекомендую; SQL 005 должен быть усилен соответствующей уникальностью.
6. **Корпоративные колонии:** личный владелец или сотрудник корпорации с актуальным colonize/manage permission; 24ч cooldown между обычными сменами. Админ отдельным правом без cooldown. Рекомендую принять.
7. **Пропущенный EN перевод:** показывать цельную RU опубликованную статью с явной отметкой fallback, не частично смешанную. Рекомендую принять.
8. **SVG uploads:** принимать только с последующей безопасной растеризацией; raw SVG в браузере не выдавать. Если rasterizer не готов — временно не принимать SVG. Trusted built-in SVG допускают голограммы.
9. **Favorites/Recent guide:** на первом релизе per-account Preferences, без серверной синхронизации (Original C пока RAM); позже можно расширить.
10. **Экстренный возврат:** отдельная server-diagnosed процедура с аудитом; штатно только через настоящий landing module. Не разрешать клиенту выбирать произвольную причину «я застрял» для мгновенного выхода.

## Неопределённости, которые нельзя решать без дополнительного аудита/согласования

- Полная статистика существующих имен и их Unicode collisions по реальной базе; отсутствие тестовой БД означает, что draft SQL не прогонялся. Нельзя выдавать это за подтверждённую миграцию.
- Конкурентность категорий и глобальных world locking в actual PostgreSQL isolation; schema250 может быть занят следующей веткой.
- Время жизни return authorization (проект 30s), допустимая дистанция от landing (проект 3–5 игровых единиц) и документированный emergency policy.
- Инфраструктура SVG rasterizer на Windows+Linux, безопасная offline среда, место media backup и storage capacity.
- Нужна ли публикация истории переименований всем игрокам или только заинтересованным/администраторам.
- Действительное поведение новой версии Cosmic/Planet на момент будущей реализации; исходники могут измениться после этого архитектурного PR.

## Формальный статус

**Подтверждённый выбор владельца:** Original C, глобальные имена с однократным правом первооткрывателя систем/планет, отдельное переименование колоний, CMS в PostgreSQL, единый полноэкранный Planet Mode, посадочный модуль как нормальный возврат и повторное использование #startup-screen.

**Предлагаются архитектором (требуют согласования):** конкретная точка события первооткрытия, legacy policy, Unicode/unique scope, colony rights/cooldown, SVG raster-only policy, EN fallback, expiry proof и emergency conditions.

**Не сделано:** ни Go, ни frontend, ни миграции, ни Game API, ни deployment; все SQL только review drafts. После принятия архитектуры владелец может отправить готовый prompt другому backend-разработчику. Это не разрешение на автослияние.
