# Cosmosimulator

Cosmosimulator — браузерная космическая экономическая игра с общим миром. Игрок начинает с небольшого корабля, исследует звёздные системы, добывает ресурсы, торгует, перевозит грузы и участвует в развитии колоний. Можно играть самостоятельно или вступить в корпорацию.

Сервер написан на Go, данные хранятся в PostgreSQL. Интерфейс работает в браузере на HTML, CSS, JavaScript и SVG. Для запуска не нужны Node.js и npm.

**Текущая версия: 0.24.3.** [Что изменилось в выпуске](release-notes/v0.24.3.md).

## Что уже работает

### Галактики, корабли и исследования

В стартовой галактике Эдем — 3000 звёздных систем. Они соединены сетью гиперкоридоров: пересечение линий на карте само по себе не означает, что между системами можно перелететь. Вторая галактика, Астерион, открывается после совместной активации портала. Администратор может создавать и настраивать дополнительные галактики.

На старте пилот получает «Пилигрим». Всего в игре 15 типов корпусов: разведчики, добывающие, грузовые и курьерские корабли. Они отличаются трюмом, запасом топлива, скоростью и возможностями добычи. Корабли покупаются на верфях, могут находиться в разных системах и выполнять задачи независимо друг от друга.

Неизвестные системы приходится сканировать. Исследование постепенно открывает объекты, а полученные сведения можно сохранять и продавать другим игрокам через станции. Купленные разведданные не считаются личным открытием.

### Добыча, рынок и логистика

Ресурсы добываются на астероидах, ледяных полях и других подходящих объектах. Месторождения имеют ограниченные квоты; конкурирующие пилоты расходуют общий остаток. Для разных материалов предусмотрено добывающее оборудование.

У торговых станций собственные запасы, ассортимент и кошельки. Можно покупать товары, бронировать их для получения в другом месте, выставлять ресурсы на продажу и заключать договоры доставки. Грузы не перемещаются между станциями мгновенно: их нужно везти на корабле.

Планировщик умеет добывать ресурсы, забирать груз, доставлять его и перевозить товары между складами. Задания продолжаются на сервере, даже если браузер закрыт. При нехватке топлива, свободного места или доступной квоты задача приостанавливается с указанием причины.

### Корпорации и колонии

Новые игроки вступают в «Академию Эдема». Позднее можно создать собственную корпорацию, приглашать участников, распределять полномочия, вести общий бюджет и финансировать совместные проекты. Корпорации строят склады, порты и колонии.

В текущих игровых данных существуют две корпорации-основателя с временными названиями «Корпорация-основатель 01» и «Корпорация-основатель 02». Их окончательные названия и лор ещё не внесены в игру. Концепция четырёх Основателей обсуждается отдельно и пока не считается реализованной механикой.

Планетарная поверхность генерируется по сохранённой географии. Есть биомы, береговая линия, реки, секторы, колониальные территории и посадочные площадки. Сохранённые сцены не меняются произвольно после перезапуска сервера.

### Высадка на планету

С версии 0.23.0 планетарный режим работает в отдельном процессе `cosmosimulator-planet`. Игрок может высадиться на доступной площадке, перемещаться по локальной 2D-сцене щелчками мыши, обходить препятствия, видеть других персонажей и переходить между соседними разрешёнными секторами с подтверждением перехода.

Корабль, с которого произведена высадка, остаётся закреплённым у планеты. Визит можно продолжить после закрытия вкладки или перезапуска планетарной службы. Космический сервер при сбое планетарного процесса продолжает работать.

Планетарная графика пока использует предварительный набор спрайтов. Часть анимаций требует доработки. Рюкзака персонажа, пешей добычи и строительства непосредственно в секторе пока нет.

[Как устроен планетарный режим](docs/planetary/README.ru.md).

### Терминал

Игровой интерфейс состоит из модулей и перемещаемых окон. Окна можно изменять в размерах, закреплять и сохранять их расположение в браузере. Доступны карты галактики и системы, управление флотом, трюм, рынок, склады, исследования, колонии, уведомления и руководство пилота. Интерфейс переведён на русский и английский языки.

## Игровое время

В Cosmosimulator используются разные способы отсчёта времени:

- **Тик** — завершённый цикл обновления игрового мира.
- **Календарные импульсы** — счётчик даты ЭД. Один период содержит 1000 импульсов, один год — 360 периодов.
- **Реальное время** — основа некоторых полётов, исследований и сроков договоров.
- **Фаза задачи** — этап её выполнения, а не единица календарного времени.

Интервал тика и количество календарных импульсов за тик настраиваются администратором. Поэтому дату ЭД нельзя автоматически переводить в земные секунды, дни или годы. Формат даты: `ЭД 0001·042·318`.

## Запуск в Windows

Нужна PostgreSQL 17 или совместимая версия. Сборки рассчитаны на Windows x64. Для космического режима достаточно одного исполняемого файла; высадка требует второй службы той же версии.

Можно использовать существующую базу PostgreSQL, выделив игре отдельную схему. `DATABASE_URL` задаёт подключение к базе, `DB_SCHEMA` — имя схемы. По умолчанию это `public`. Если схема отсутствует, служба сможет создать её при наличии права `CREATE` на базу. Роль службы должна иметь необходимые права на схему, таблицы и последовательности.

Пример консольного запуска космической службы в PowerShell:

```powershell
$env:DATABASE_URL = 'postgres://cosmos:URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable'
$env:DB_SCHEMA = 'cosmosimulator'
$env:HTTP_ADDR = '127.0.0.1:8080'
$env:PLANET_ENABLED = 'true'
$env:PLANET_INTERNAL_URL = 'http://127.0.0.1:8081'

# Задаются только при первоначальном создании администратора.
$env:ADMIN_USERNAME = 'operator'
$env:ADMIN_PASSWORD = 'REPLACE_WITH_A_UNIQUE_PASSWORD'

.\downloads\cosmosimulator-v0.24.3-windows-amd64.exe
```

После запуска откройте `http://127.0.0.1:8080`. Для остановки используйте Ctrl+C. После создания администратора уберите `ADMIN_USERNAME` и `ADMIN_PASSWORD` из окружения последующих запусков.

Чтобы включить высадку, откройте **второе окно PowerShell** и запустите планетарную службу. Ниже пример с тем же логином PostgreSQL для локальной проверки; для постоянной установки рекомендуется отдельная роль с ограниченными правами.

```powershell
$env:DATABASE_URL = 'postgres://cosmos:URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable'
$env:DB_SCHEMA = 'cosmosimulator'
$env:PLANET_HTTP_ADDR = '127.0.0.1:8081'

.\downloads\cosmosimulator-planet-v0.24.3-windows-amd64.exe
```

Обе службы используют одну базу и одну схему. Миграции выполняет космическая служба; планетарная не должна запускаться первой при обновлении схемы. В браузере нужен только порт космической службы: запросы к планетарной проходят через её шлюз.

Файл [`.env.example`](.env.example) содержит остальные параметры. Исполняемые файлы **не читают `.env` автоматически**.

Подробная инструкция по установке двух Windows-служб, правам PostgreSQL, обновлению и восстановлению: [docs/planetary/P2-10/README.ru.md](docs/planetary/P2-10/README.ru.md).

## Обновление и безопасность

Перед обновлением остановите сначала планетарную, затем космическую службу. Сделайте резервную копию игровой схемы, замените оба исполняемых файла на сборки одной версии и запустите сначала космическую, затем планетарную службу. Не запускайте две активные планетарные службы на одной схеме.

Миграции могут быть несовместимы со старыми выпусками. В частности, версию 0.3.2 нельзя запускать на схеме, обновлённой миграцией 0.3.3. Для возврата к старой схеме потребуется соответствующая резервная копия.

Для публичного доступа используйте HTTPS-прокси, задайте точный `PUBLIC_ORIGIN`, включите `COOKIE_SECURE=true` и настройте `TRUSTED_PROXIES` только для адресов своего прокси. Не публикуйте строки подключения, пароли и токены. Для удалённой PostgreSQL используйте соединение с проверкой TLS.

В 0.23.0 проверена работа двух процессов с 50 авторизованными протокольными клиентами и восстановление после аварийного завершения планетарной службы. Нагрузочные испытания проводились на Linux. Это не измерение производительности 50 браузеров или Windows-сервера. [Условия и результаты](docs/planetary/P2-9/REPORT.ru.md).

## Разработка

Нужны Go 1.26+ и PostgreSQL для интеграционных проверок. Для обычной проверки исходников:

```sh
go mod download
go vet ./...
go test ./...
```

Интеграционные тесты используют `TEST_DATABASE_URL` и отдельную тестовую базу с суффиксом `_test`. Если переменная не задана, требующие PostgreSQL тесты пропускаются.

Сборка для Windows x64 из корня репозитория:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -buildvcs=false -trimpath -ldflags='-s -w' -o downloads/cosmosimulator-v0.24.3-windows-amd64.exe ./cmd/cosmosimulator
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -buildvcs=false -trimpath -ldflags='-s -w' -o downloads/cosmosimulator-planet-v0.24.3-windows-amd64.exe ./cmd/cosmosimulator-planet
```

Управление космическим сервером находится в `internal/server` и профильных Go-пакетах; браузерные ресурсы — в `internal/server/web`. Node/Playwright применяются при разработке и тестировании интерфейса, но не нужны для работы Windows-сборок.
