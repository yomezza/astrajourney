# UI/UX — лаборатория интерфейса Cosmosimulator

Модуль установлен только в `scripts/frontend-generation/`. В рабочий frontend игры он не встраивается, PostgreSQL и игровые службы не использует. После обновления демосреды откройте **UI/UX** в левом меню. Пункт находится выше нижней группы (Чат, Руководство, Предложить идею), поэтому позиция Чата сохранена. Окно работает через исходный `Modules`: открытие, закрытие, resize, перемещение, pin и maximize.

## Структура

- `catalog.json` — единый источник метаданных: канонический ID, имя RU/EN, сокращения, категория и подкатегория, тип, вариант, renderer, source JS/CSS, селекторы, применение, тестовые состояния, статус проверки.
- `lab.js` — контроллер левой навигации, поиска, интерактивных проб, RU/EN, сравнения и очистки временных popup.
- `lab.css` — только оформление лаборатории, правила ограничены `.uiux-*`. Производственные CSS и утверждённые файлы чата/исследований не изменяются.
- `AUDIT.ru.md` — аудит, ограничения и кандидаты для сравнения.

## Как пользоваться

Слева выберите категорию, при необходимости подкатегорию, либо «Все». Поиск справа принимает ID, название, сокращение, путь к исходнику и CSS-класс. Наведение на ID показывает карточку RU/EN, сокращения, тип и применение. Есть кнопка «Копировать ID». «Сравнить» отмечает до четырёх компонентов и располагает интерактивные пробы рядом с данными CSSOM (шрифт, отступы, рамка, фон). Переключатель RU/EN относится только к лаборатории. Флажок «Узкая область» проверяет ограничение ширины.

Меню, picker, формы, таблицы, progress, вкладки, SVG и окна кликабельны. Компактные popup появляются вне прокручиваемого dialog, закрываются по Escape/клику вне/прокрутке/resize/закрытию модуля. Все операции локальны.

## Статусы

- `original`: лаборатория вызывает реальную общую функцию из original-web (`UI.menu`, `UI.picker`, `UI.bar`, `Modules` и др.).
- `approved`: оформление уже утверждено для чата v13 или исследований v13, а демонстрационная интерактивная логика **изолирована** от рабочего контроллера.
- `adapter`: тип найден в игре, пример сознательно упрощён и не имитирует реальные игровые команды.
- `pending`: источник известен, но полноценный изолированный интерактивный renderer пока не готов; указан блокер.

Эти категории **не** означают, что все 156 записей имеют production-equivalent поведение. Полный backend-зависимый renderer требует отдельной задачи.

## Добавление компонента

1. Сверьте реальный исходник в `internal/server/web` либо согласованном демо-коде и определите статус.
2. Добавьте **одну запись** в `catalog.json / components`: уникальный `ui.type.variant`, двуязычные имена и сокращения, category, subcategory, renderer, sources, CSS selectors, uses, status, states. Не создавайте новый тип для каждого экземпляра (например, отдельного корабля).
3. Повторно используйте renderer, если его поведение подходит. Иначе создайте безопасный изолированный пример в `lab.js`, не обращающийся к реальному backend.
4. Пересчитайте `categories[].count` из `components[]`. Проверьте уникальность и валидность ID.
5. Запустите `python -m unittest discover -s tests -v` и после `prepare.py` — `python ui-registry-scan.py`. Сканер — эвристика, не доказательство полного охвата.
6. Проверьте desktop/mobile, клавиатуру, позиционирование popup и отсутствие ошибок Console.

Спецификация уровней type/application/instance находится в `docs/ideas/ui-element-registry/02-naming-convention.ru.md`. Утверждение варианта в лаборатории само по себе не изменяет чат v13, исследования v13 или production-компонент.
