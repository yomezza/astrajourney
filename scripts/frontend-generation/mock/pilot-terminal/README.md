# Pilot Command Terminal — изолированный интерактивный прототип

Прототип концепции [единого командного терминала](../../../../docs/ideas/pilot-command-terminal/README.ru.md)
и [frontend-архитектуры](../../../../docs/ideas/pilot-command-terminal/02-frontend-architecture-prototype.ru.md).

**Только `scripts/frontend-generation/`.** Не меняет `internal/server/web/`, API,
схему БД или production-окна. Не создаёт дополнительных Chat Service, сокетов или
второго оконного менеджера.

## Запуск

```bash
cd scripts/frontend-generation
./start.sh
# либо python launch.py
```

Открыть <http://127.0.0.1:8765/?pilot-terminal=1>, авторизоваться
в фиктивной демосреде. В боковом меню также есть «Терминал · проба».
Для работы необходим подготовленный `original-web` из существующего
`prepare.py` / `launch.py`.

## Сценарий

Изначально созданы «Добыча — 1» (корабль «Пилигрим» #41) и
«Добыча — 2» (одноимённый «Пилигрим» #82). Каждый workspace имеет
свои окна «Корабль», «Трюм», «Добыча» и «Справка». Под вкладками находится
контекстный выбор корабля пространства, рядом — операции над вкладками.
Кнопка «Все модули» открывает каталог четырёх mock типов. Существующая
`Modules.create()` создаёт **плавающие** окна с уникальными ID; их можно
перетаскивать за заголовок, менять размеры за край и двигать клавиатурой
(фокус заголовка + стрелки). Крестик убирает экземпляр из рабочей сцены;
тот же тип можно снова добавить из каталога.

Привязки:
- `workspace` — используется `workspace.shipId`;
- `fixed` — `binding.shipId` не меняется при смене корабля пространства;
- `none` — независимая «Справка».

«Все модули» ограничен одним экземпляром каждого типа в одном workspace.
При смене вкладки окна закрываются и уничтожаются только по префиксу
`ptdemo-`, а их компоновка уже сохранена штатным менеджером.

## Сохранение

`Preferences.key("pilot-terminal",{account:accountId,version:1})`
хранит только именования/порядок/контексты/дескрипторы/фильтры. Оригинальные
`module:<windowId>` ключи `Preferences` сохраняют x/y/width/height/pinned
для отдельных экземпляров. ID вида `ptdemo-u<account>-w<workspace UUID>-i<instance UUID>`
не совпадают с ID существующих игровых модулей. После обновления страницы
настройки и окно выбранного workspace восстанавливаются.

Демо-переключатель «Mock аккаунт: A/B» использует `Session.data.state.user.id`
как основу и добавляет суффикс `-sandbox-B` для тестирования изоляции.
**Это не логин и не смена настоящего аккаунта.** При `signedout` терминал
уничтожает только свои окна; данные разных account scopes не смешиваются.
Если `localStorage` недоступен, `Preferences` работает в памяти;
интерфейс показывает предупреждение.

Все источники данных в `fixtures.js`: два вымышленных корабля, разные
грузы и месторождения. Кнопки «Демо: добыть» пишут цель в локальный журнал,
**никаких POST/fetch/API/игровых команд**. Скрытие #82 — тест пропавшего
корабля; выбранные ID не переназначаются.

Общие чат, уведомления, confirm/modal и новости остаются исходными,
вне workspace-экземпляров. Оригинальные `createFleet/createMining`
не импортируются.

## Проверки

```bash
python -m unittest tests.test_pilot_terminal -v
# Требуются запущенный localhost demo, playwright и Chromium:
python tests/browser_pilot_terminal_smoke.py
```

Браузерный тест проверяет смену корабля, фильтры, геометрию,
F5, дублирование и отсутствие реальных mutation API запросов.
Тест требует полноценный `original-web`, а не только исходные файлы POC.

**Ограничения:** пока нет серверного хранения или синхронизации;
источник кораблей полностью mock; в узком окне floating-окна могут
перекрывать друг друга, их можно переставлять штатным Modules;
UI-адаптеры intentionally read-only, дублирование окон одного типа
в пределах одной вкладки пока не поддерживается.
