# Названия, версия игры и галактики · 0.28.0

## Права игрока

Первооткрыватель **системы** может один раз назвать систему и отдельно, по одному
разу, каждую её планету. Расход права на систему не расходует права планет.
Исторический автор первого сканирования планеты сохраняется: это атрибуция
открытия, а не источник права на название. Для старых исследований без
достоверного первооткрывателя системы владелец права не придумывается.

**Астероидные и ледяные поля игрок не переименовывает** — уточнение владельца
проекта заменяет раннее предложение дать такое право. Генерируемые станции
тоже недоступны для переименования. У станций есть `name_origin` и `created_by`:
`generated`, `player` или `legacy_custom`; неизвестный исторический создатель
остаётся NULL. Размещение личных станций в этом выпуске не добавлено.

Системы основателей и их планеты защищены и фактическим `founder` системы,
и записью реестра. UUID сопоставляется с типом и числовыми локаторами на сервере.
Повторная новая операция расходования права возвращает 409, чужой игрок — 403.
Тот же успешно выполненный идемпотентный запрос возвращает прежний результат.
Блокировка мира и строк реестра защищает конкурентные операции; имя, расход
права и история коммитятся вместе. Административное исправление с причиной
и аудитом не восстанавливает израсходованное право.

В «Исследованиях» кнопка системы исчезает после сохранения. «Подробнее» открывает
отдельное окно «Последовательность объектов системы». Щелчок по планете открывает
компактное меню переименования; после использования действие отключено.
Характеристики остаются доступны в подсказках. Поля и станции такого действия
не получают.

## Словари PostgreSQL

Для установки `database.schema = "game"` схема называется `game_dictionaries`.
Для остальных корней используется `dblayout.Schema(root, "dictionaries")`,
включая существующее хеширование длинных/нестандартных имён установки.

Таблицы: `system_names`, `planet_names`, `station_names`, `asteroid_names`,
`ice_field_names`, `anomaly_names`. Генерации аномалий нет. В каждой таблице:
`id`, `word`, `part` (`base` или `suffix`), `active`. Новые схема, таблицы и столбцы
имеют русские COMMENT ON.

Начальное наполнение содержит 607 английских основ и 37 научных фамилий латиницей
на словарь: 22 459 сочетаний до числового суффикса. Наполнение фиксируется
`name_dictionary_state` один раз в транзакции: ручные правки, отключения и удаления
не восстанавливаются при запуске. Генератор читает активные строки PostgreSQL;
при нехватке активной основы или окончания возвращает явную ошибку. Встроенных
списков имён в Go больше нет; технические ID генератора не заменяют словари
рабочей установки.

Пример правки словаря владельцем тестовой/администрируемой установки:

```sql
UPDATE game_dictionaries.station_names SET active = false WHERE id = 1;
INSERT INTO game_dictionaries.station_names(word, part) VALUES ('Faraday', 'base');
```

Существующие имена систем и планет сохраняются. Новые системы и планеты, в том
числе галактики администратора, используют словари. Природные поля хранятся в
`system_objects` с постоянными UUID и именами, без изменения их ресурсов/орбит.
Опрос состояния не запускает генерацию и не перечитывает весь мир: остаётся
прежняя проверка `universe_state.storage_version`.

Все прежние генерируемые станции, включая неактивные, получают самостоятельные
английские имена. Уникальный индекс `lower(btrim(name))` охватывает все галактики
и неактивные станции. Монотонный курсор обеспечивает числовые суффиксы без
повторного перебора занятого пространства. Имена построенных станций сохраняются;
старые коллизии разрешаются в порядке `(star, object_id)` с числовым суффиксом,
резервированием всех исходных имён и записью `station_name_collision` в `admin_log`.
Переименование системы не переименовывает станции. Идентификаторы, имущество,
договоры и маршруты остаются прежними.

## Единая отображаемая версия

Источник версии страниц — единственная запись `game_ops.game_release`, которую
публичный `/api/server-status` возвращает в поле `version`. HTML не содержит
номера релиза: шапка и подвал обновляются из этого ответа. Пока сервер недоступен,
виден многоточечный индикатор вместо выдуманной версии.

Для изменения отображаемой версии достаточно одной записи:

```sql
UPDATE game_ops.game_release SET version = '0.28.0', updated_at = clock_timestamp()
WHERE id = 1;
```

Обычный перезапуск сохраняет эту правку. Следующая релизная миграция обновляет
номер один раз по полю `migration`. Техническая версия исполняемых служб в health
и диагностике остаётся версией их сборки; изменение текста в БД не обновляет EXE.

## Карты, рынок и пустые галактики

Списки систем на карте галактики, внутри системы и во вкладке «Маршрут» ограничены
выбранной галактикой. Поиск и избранное работают внутри того же набора.
Станции глобального рынка и каталог верфей ограничены галактикой активного корабля;
метаданные мира загружаются и при первом открытии рынка без посещения карты.
Это фильтрация интерфейса; существующие серверные права покупки/стыковки сохранены.

При создании галактики доступен флаг `empty`: системы, планеты, поля и коридоры
генерируются, но основатели и станции отсутствуют, включая центральные системы.
Режим хранится в `galaxy_catalog.empty` и сохраняется при последующем расширении.
Для существующей населённой галактики это не команда удаления станций.

## Обновление

1. Остановить Chat, Planet и Cosmic; сделать согласованный backup всей установки.
2. Сохранить прежний корень схемы, пути данных и журнал Chat.
3. Запустить Cosmic 0.28.0 первым с правами миграции. Он атомарно создаёт словари,
   обновляет имена станций, заполняет поля и версию игры; раскладка схем становится 2.
4. После готовности Cosmic запустить Planet и Chat той же версии.
5. Проверить `/api/server-status`, health служб и личный интерфейс.

Planet schema остаётся 10, Chat schema — 1, формат мира — 1. Не редактировать
`search_path` вручную. `--check-schemas` выполняет проверку без записи. Откат
на старые бинарники требует восстановления согласованного backup: раскладка 2
не должна открываться старым Cosmic для записи.

Проверки выполнялись только в одноразовых локальных `_test` базах. Реальная
проверка обновления с опубликованного бинарника 0.27.0 и сохранённые хеши:
[v0.28.0/upgrade-result.json](v0.28.0/upgrade-result.json).
