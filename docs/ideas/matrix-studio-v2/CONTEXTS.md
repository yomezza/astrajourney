# Контексты и привязки

## Рабочее пространство
Основной контекст — опциональный ship_id. Дополнительные контексты пространства (станция, колония, корпорация, система, планета) не утверждены: сначала отдельные сценарии и доказательство пользы массовой смены контекста. Сейчас не вводить их; архитектура расширяема. Независимые фиксированные объекты в модулях и плавающих окнах допустимы.

## Правила привязки
| Режим | Семантика |
| --- | --- |
| workspace | Следовать кораблю текущего пространства |
| fixed | Стабильный ID конкретного объекта, включая другой собственный корабль |
| derived | Объект, вычисляемый из разрешённого контекста: текущая станция стыковки, система, трюм |
| global | Данные аккаунта/мира без выбора конкретного корабля |

Названия режимов — согласованная семантика, wire format уточняется (старый none требует явной миграции, а не механического переименования). Пример логического дескриптора: type=inventory, purpose=storage, binding={mode:derived, source:workspace.ship, relation:docked_station, entity_type:personal_warehouse}. Для fixed: entity_type и entity_id; состав идентификатора станции/склада уточнить по фактической схеме. Не использовать отображаемые имена как IDs. Не хранить вычисленный ID вместо правила, если привязка должна следовать объекту.

Корабль пространства и фиксированный собственный корабль используют один подвид ship.owned. Временное окно сохраняет исходный объект при смене пространства: при открытии из контекста зафиксировать разрешённый исходный якорь (например, ship_id), производный объект при необходимости продолжает следовать именно этому кораблю, а не новой вкладке. Точное поведение derived в плавающих окнах — техническое предложение для согласования; запрет тихой смены целевого корабля обязателен.

Пример рынка (M007 не входит в реализацию): автоматически следует текущей станции стыковки корабля либо фиксированной выбранной станции. При отсутствии стыковки — явное отсутствие контекста, не подставлять произвольную станцию. Просмотр удалённого объекта не означает разрешение на удалённые операции. Аналогично склад.

## Разрешение и безопасность
Разрешать контекст отдельно для экземпляра, проверять доступ при чтении и каждой мутации. Контекст просмотра не равен server active ship. Не вызывать select_ship для открытия, смены пространства, исполнения операции или имитации изоляции. Если API не поддерживает явный target, Backend добавляет безопасный контракт; до этого действие недоступно с пояснением. Не подменять Session.data.expedition. При потере доступа/продаже объекта — «Объект недоступен», сохранить идентификатор для объяснения, предложить явно выбрать замену; не подставлять первый объект или active ship. При смене цели сбрасывать устаревшие данные и черновики команд, игнорировать поздние ответы по прежней цели. Заголовок каждого контекстного модуля всегда показывает объект (имя + различимый ID или однозначный идентификатор), тип привязки и понятное состояние недоступности.
