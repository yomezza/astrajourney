# Работа ИИ-разработчиков Astra Journey

Этот каталог предназначен для **заданий, промптов, подтверждённых передач контекста и шаблонов**. Он не заменяет игровой код, концепции и системную документацию.

**Первое чтение:** [AGENTS.md](../AGENTS.md) → [правила организации](../docs/repository-organization.ru.md) → [документация проекта](../docs/README.md) → соответствующая задача.

> **Ветка отвечает на вопрос «над чем сейчас работаем?», а каталог — «что это за материал и кому он предназначен?»**

## Где что хранится

- [prompts/](prompts/README.md) — задачи **по роли**, с независимой сквозной нумерацией внутри роли.
- [handoffs/](handoffs/README.md) — краткие отчёты, чтобы новый чат мог продолжить работу без выдуманного контекста.
- [templates/prompt.md](templates/prompt.md) — шаблон нового задания.
- [templates/handoff.md](templates/handoff.md) — шаблон передачи результата.
- [docs/ideas/](../docs/ideas/README.md) — **единственные основные источники самих концепций**. В промптах на них ссылаемся.

## Имена заданий

`ai/prompts/<role>/<NNN>-<slug>/prompt.md`

Например: `ai/prompts/frontend/001-pilot-command-terminal/prompt.md`.

`NNN` — новый уникальный номер **внутри каталога роли** (001, 002, ...); `slug` — короткая тема в нижнем регистре на латинице через дефис. Номер выдаётся по появлению новых каталогов в `ai/prompts/<role>/`; не перенумеровывай старые задания. **Этот счётчик начат при создании `ai/` и не претендует на номера исторических чат-сессий.**

Роль задаётся по ответственности, а не по конкретной учётной записи чата:
`architecture/`, `frontend/`, `backend/`, `dba/`, `graphics/`, `svg/`.

Существующие названия и документы в `docs/ideas/`, `docs/operations/` и других каталогах **не переносить** ради этой системы.

## Что должно быть в задании

- Ссылка на `AGENTS.md`, текущий `main` и на главный документ идеи.
- **Статус**: исторический пример / подготовлено к выдаче / в работе / выполнено. Наличие файла не запускает работу.
- Внятная задача, границы (что **не** изменять), права на Git/БД/API.
- Как проверить результат; где его оставить (каталог, ветка, PR).
- Обязательный финальный отчёт с **реальными** файлами, проверками и SHA.

Исполнитель не должен выводить «завершено» только потому, что промпт создан. Каждый новый чат получает конкретную инструкцию от владельца.

## Ответственность ролей

| Роль | Основная зона | Ограничение |
| --- | --- | --- |
| Architecture | контракты, риски, план внедрения | не менять production без команды |
| Frontend | vanilla JS/CSS, UI, mock-стенды | для эксперимента использовать `scripts/frontend-generation/` |
| Backend | Go, игровые команды, службы | соблюдать контракт API и тесты |
| DBA | PostgreSQL, миграции, безопасность | не выполнять SQL на рабочей БД без отдельного разрешения |
| Graphics | художественный стиль, исходные ассеты | проверять [дизайн](../docs/design/README.md), не менять API игры |
| SVG | SVG/голограммы/интеграция графики | совместимость с текущими UI-компонентами |

Ролевые каталоги могут содержать собственный `README.md`, но основные правила едины. Никакие секреты, токены, доступы, локальные IP-адреса и личные данные не включать в промпты или handoff.
