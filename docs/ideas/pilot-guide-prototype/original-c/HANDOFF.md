# Frontend handoff: будущий перенос Original C

**Статус:** материал для отдельного согласования / разработки через новый PR. **Не переносить автоматически.**

## Предмет передачи

Владелец выбрал **исходный вариант C «База знаний пилота»** с поиском над двухпанельным списком, вкладками «Все темы / Избранное / Недавние», категориями-chip и чтением справа. Опубликованное демо содержит две корректировки: сохраняемая прокрутка и демонстрационные SVG-проекции с полным 360° оборотом.

Откройте `index.html`, затем прочитайте `STYLE_GUIDE.md` (палитра и точные CSS-классы) и `FUNCTIONALITY.md` (контракты/фиктивные функции).

## Рекомендуемый план для разработчика

1. Проверить актуальный `main`, `AGENTS.md`, `internal/server/web/features/guide/index.js`, `internal/server/web/features/objects/presentation.js`, `internal/server/web/styles/chat.css`, `internal/server/web/ui/windows.js`, а также полную документацию прототипа. Не переносить слепо устаревшие пути.
2. Использовать **существующее** окно `#window-guide .module-content`. В коде `createGuide()` заменить только *компоновку содержимого*, а не модульный контейнер, titlebar, заголовок, перетаскивание, закрепление или `Modules.open('guide')`.
3. Подать на UI текущий production-каталог: `d().resources`, `w().ship_classes`, `objectArticles`, технический раздел. Сохранить `UI.hologram`, `objectHologram()`, `shipStats()`, `filterShipyards()`, `Game.openShipyards()`, связанную навигацию; сохранить `I18n.t` и отдельные тексты/опции для RU/EN.
4. CSS переносить из `.mode-c`, `.c-hero`, `.c-tabs`, `.c-main`, `.c-index`, `.c-reading`, `.result-row`, `.article-pane`, `.holo-frame` **только в scope `#window-guide`**. Использовать имеющиеся CSS tokens, если они дают подходящий вид. **Не переносить** общие селекторы `body`, `button`, `.app-header`, demo `.stage` и пользовательское demo-окно.
5. Обработчики выбора статьи должны не сбрасывать прокрутку независимого списка и области чтения. Предпочтителен частичный DOM update, иначе — слепок `scrollTop/scrollLeft` + восстановление и `focus({preventScroll:true})`.
6. В космических статьях оставить настоящий `objectHologram()`, показывающий официальные игровые `object-*.svg`. Убедиться, что SVG-ассеты выполняют **полный** оборот 360° по Y без скачка на 180°. При необходимости исправлять графические SVG и/или их генерацию в отдельном review; `hologram.js` — **только эталон математически непрерывного цикла**, а не production-замена.
7. Избранное и недавние — **новые идеи UI, отсутствующие в текущем guide/index.js**. Согласовать жизненный цикл: можно начать с памяти окна; если требуется сохранение, безопасно использовать per-user `Preferences` или согласованную существующую модель данных, не создавая новый API автоматически. Исключить перенос состояния между аккаунтами и утечки после `signedout`.
8. Проверить маленькие окна (420×580 и менее), большое окно, длинные названия, ресурсную таблицу, длинную статью, пустой поиск/каталог, видимость SVG, непрерывность вращения и скролл, `Session.epoch` при смене пользователя, RU/EN, действия кораблей и связанных ресурсов.
9. Подготовить отдельную feature-ветку и PR, приложить diff и скриншоты вне self-contained ZIP. **Не выполнять merge без одобрения владельца.**

## Основные риски

- В реальном руководстве справочник генерируется из серверных данных. Прототипный статический массив `fixtures.js` **не источник истины**.
- Новая табовая навигация потребует аккуратного разделения состояния UI по аккаунтам.
- SVG-графика большой сложности; тестовый `hologram.js` процедурный и не соответствует арт-ассетам побайтово.
- UI-обвязка прототипа имитирует окно, поэтому нельзя создавать вторую панель titlebar внутри Modules.
- Демо использует русские строки и не покрывает обязательную production-локализацию.

**Границы текущей публикации:** только `docs/ideas/pilot-guide-prototype/original-c/` в отдельной ветке, никаких изменений `internal/server/web`, Go, SQL, API, конфигураций, данных или `main`.
