# AstraJourney Web · 0.30.3

Пятая Go-служба владеет браузерным интерфейсом и публичным HTTP-шлюзом. Официальная поставка 0.30.3 — Linux amd64. [Релиз и файлы](https://github.com/yomezza/astrajourney/releases/tag/v0.30.3).

## Пять служб

| Служба | Адрес по умолчанию | Назначение |
|---|---|---|
| Web | `127.0.0.1:8083` | HTML/CSS/JS/локализации, HTTP-шлюз для браузера |
| Cosmic | `127.0.0.1:8080` | Игровой API, права доступа, PostgreSQL, симуляция |
| Planet | `127.0.0.1:8081` | Локальные сцены и WebSocket |
| Chat | `127.0.0.1:8082` | Чат и WebSocket |
| CDN | `127.0.0.1:8084` | Графика и приватные изображения руководства |

Игрок открывает **Web**. Web напрямую передаёт `/api/` в Cosmic, изображения и `/api/guide/media/` — в CDN, разрешённые HTTP/WS-маршруты Planet/Chat — в эти службы. Непубличные `/internal/`, `/cdn/internal/`, метрики и произвольные пути Planet/Chat наружу не передаются. Шлюз сохраняет cookie, Origin, методы и тела запросов, удаляет поступивший от браузера служебный токен CDN и заново формирует X-Forwarded-заголовки. Внутренние службы следует слушать на loopback или закрытой сети.

Web и CDN не подключаются к SQL. Cosmic больше не содержит HTML/CSS/JS в `embed.FS` и не раздаёт интерфейс. CDN больше не проксирует остальные запросы в Cosmic. Права на приватные изображения по-прежнему подтверждает Cosmic для каждого обращения, включая условные запросы; кеш публичного каталога не используется для приватного контента.

## Локальная сборка

Требуется Go 1.26.0. Node.js нужен только для браузерных тестов.

```bash
python3 scripts/build-release.py v0.30.3 --platform linux --out dist/review
python3 scripts/verify-web-release.py v0.30.3 --directory dist/review
sha256sum -c dist/review/SHA256SUMS
```

Команды создают локальные сборки, два внешних пакета, JSON-индексы и контрольные суммы. Они не публикуют релиз. Старые файлы `downloads/` не перезаписываются. Для проверки неопубликованных изменений или офлайн-установки установить оба пакета локально и использовать `sync_enabled=false`. Официальный выпуск получает пакеты с GitHub при `sync_enabled=true` и `web.release_tag='v0.30.3'`.

Отдельно собрать интерфейс:

```bash
go run ./cmd/astra-web-assets -root web -tag v0.30.3 -out dist/web
```

Исходники интерфейса находятся в `web/`; графика — в `assets/game/`. Пакет Web принимает только HTML, CSS, JS и JSON. Имена путей, количество/размеры файлов, SHA-256 каждого файла, ревизия и контракты `astra-web-v1` / `astra-api-v1` проверяются до активации. Символические ссылки, обход каталогов, повторяющиеся и незаявленные файлы отклоняются.

## Настройка и перенос с 0.29.0

Общий пример — [shared.example.toml](../../configs/shared.example.toml); отдельный — [web.example.toml](../../configs/web.example.toml).

1. Сохранить прежние `database.schema`, пути CDN, файл `service.token`, журнал Chat и согласованную резервную копию БД/приватных изображений.
2. Остановить старые процессы. Перевести CDN на `127.0.0.1:8084`, исправить `[cosmos] cdn_internal_url` на этот же адрес. `storage_root` и `service_token_file` оставить прежними.
3. Добавить `[web]` из примера: внешний адрес `:8083`, внутренние адреса остальных четырёх служб. Для доступа из LAN слушать `0.0.0.0:8083`.
4. `[cosmos] public_origin`, `[planet] allowed_origins` и `[chat] allowed_origins` должны содержать адрес **Web**, который игрок открывает в браузере. В `cosmos.trusted_proxies` доверять только адресу Web.
5. Для автоматической загрузки оставить `sync_enabled=true` в Web/CDN и `web.release_tag='v0.30.3'`; дождаться готовности пакетов. Для офлайн-установки использовать команды ниже. `CONFIG_FILE` должен быть абсолютным. Все пути из TOML разрешаются относительно самого файла.

```bash
export CONFIG_FILE='/etc/astra-journey/shared.toml'
chmod +x ./astra-journey*-v0.30.3-linux-amd64
./astra-journey-cdn-v0.30.3-linux-amd64 --install-pack './astra-journey-assets-<revision>.zip'
./astra-journey-web-v0.30.3-linux-amd64 --install-pack './astra-journey-web-<revision>.zip'
```

`--install-pack` устанавливает пакет и **завершается**; это не запуск службы. Затем запустить Cosmic (он применяет миграцию), Planet, Chat, CDN и Web обычными командами без этого флага. Web сообщает установку в консоли. Отдельный токен для Web не требуется.

Для systemd есть [пример Web unit](../../configs/systemd/astra-journey-web.service). При размещении `CONFIG_FILE` в `/etc/astra-journey/` указать абсолютные `storage_root`: `/var/lib/astra-journey/web` и `/var/lib/astra-journey/cdn`; путь токена в Cosmic/CDN — `/var/lib/astra-journey/cdn/state/service.token`. Это соответствует каталогам `StateDirectory`, доступным пользователю службы.

Миграция `schema300.sql` добавляет основателей 03/04, не присваивая себе существующие названия/теги игрока, и один раз обновляет строку версии игры. Последующие изменения версии оператором в `game_release` переживают перезапуск. Территории сохранённого мира и существующие ID основателей не перераспределяются; четыре основателя участвуют в новой генерации, пустые галактики остаются пустыми.

## Каталоги и обновление

```text
data/web/
  packs/<revision>/       проверенные HTML/CSS/JS/JSON + manifest.json
  staging/               загрузка и проверка до установки
  state/active.json      активная и предыдущая ревизии
  state/owner.lock        один владелец каталога
```

Web получает пакет из **опубликованного тега**, указанного в `release_tag`, из фиксированного репозитория. Ветка `main`, адреса из NATS и пользовательские URL не используются. Таймер не переводит интерфейс на произвольную более новую версию API. Новый пакет активируется только после полной проверки; неудачная загрузка оставляет прежний активным. На старте повреждённая активная ревизия заменяется проверенной предыдущей.

HTML отдаётся с `no-cache` и ссылается на `/web/<revision>/...`. Эти файлы и графика `/assets/sha256/...` имеют длительный immutable-кеш. Открытая вкладка продолжает импортировать свою версию JavaScript даже после обновления; сохранённые пакеты автоматически не удаляются. Локализации также берутся из конкретной ревизии. Пользовательские API и приватные медиа не получают публичный кеш.

Для отката остановить Web, отключить синхронизацию, выполнить `./astra-journey-web-v0.30.3-linux-amd64 --activate <previous-revision>` и снова запустить. Не удалять старые пакеты, пока ими могут пользоваться открытые страницы. Резервировать `data/web` можно отдельно от БД: этот каталог содержит только публичный интерфейс и состояние активации.

Readiness: `GET /web/api/v1/health/ready` — пакет установлен и Cosmic подтверждает совместимый HTTP-контракт. Liveness: `/web/api/v1/health/live`. Все пять служб доступны администратору в категории «Службы и диагностика».

## NATS и кеш каталога

При `nats.enabled=true` Web использует отдельный профиль `[nats.web]`, identity/username `web`. Учетную запись нужно добавить в конфигурацию своего брокера самостоятельно; настройки брокера задаются отдельно. TLS и обычный NATS поддерживаются общим клиентом служб.

| Identity | Publish | Subscribe |
|---|---|---|
| web | запрещён | `cosmos.v1.signal.cdn.assets.ready`, `cosmos.v1.signal.cdn.assets.changed` |

Фрагмент ACL: [web-nats-auth.config.example](web-nats-auth.config.example). Это дополнение к существующим пользователям Cosmic/Planet/Chat/CDN, а не замена конфигурации брокера.

Web держит только публичный `asset-map` не более 30 секунд. Валидный сигнал CDN немедленно инвалидирует его; следующее обращение заново читает HTTP-каталог CDN. После переподключения кеш также инвалидируется. Обработчик NATS не обращается к БД и не загружает файлы. При отключённом брокере действует тот же HTTP-путь с TTL, раздача интерфейса и графики продолжается.

NATS не подтверждает загрузку текстур конкретным браузером и не получает пользовательские cookie или содержимое ассетов. Готовность окна определяет клиент по завершению данных, обязательной подготовки Canvas и декодированию eager-изображений. Успешное получение сигнала не выдаёт игровые права и не меняет состояние задач планировщика.

## Контракт нового модуля

Оболочка каждого окна создаёт внутренний загрузчик в стиле стартовой страницы. Основной контент остаётся недоступным для кликов и клавиатуры до готовности. Есть ограничение ожидания, повторная попытка, отмена при закрытии и проверка поколения сессии. Фоновые обновления готового окна не включают загрузчик заново.

```js
const root = Modules.create("new-module", "Название", 800, 600);
Modules.prepare("new-module", async signal => {
  const epoch = Session.epoch;
  const data = await api("module-data", undefined, signal);
  if (signal.aborted || epoch !== Session.epoch) return;
  render(root, data);
  await prepareCanvasIfNeeded(data, signal);
});
Modules.open("new-module");
```

Для вложенного просмотра использовать `Modules.load(id, async signal => ...)`; для существующего обработчика `moduleopen` — `Modules.wait(id, promise)`. Возвращать/ожидать все обязательные операции, проверять отмену перед записью DOM. Eager-изображения оболочка ждёт сама; lazy-изображения за пределами первого просмотра загружаются по мере необходимости. Событие `moduleready` испускается только после готовности. Операции изменения игры остаются обычными авторизованными API-командами.
