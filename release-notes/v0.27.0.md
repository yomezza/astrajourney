# Astra Journey 0.27.0

Игровые таблицы распределены по предметным схемам PostgreSQL. Прежнее имя
`database.schema` остаётся корнем установки: например, `game` → `game_identity`,
`game_universe`, `game_fleet`, `game_economy`, `game_corporations`, `game_colonies`,
`game_planet`, `game_chat`, `game_knowledge`, `game_integration`, `game_ops`,
`game_archive`. Несколько установок в одной БД изолированы.

**Вручную задавать `search_path` в БД не требуется.** Все службы устанавливают
его для каждого соединения. Обычные запросы сохраняют короткие имена таблиц.
Исправлены функции межсервисного доступа, создание секций, обслуживание Chat,
его выдача прав, блокировки и канал PostgreSQL LISTEN после переноса.

Перенос выполняет Cosmic в транзакции через `ALTER … SET SCHEMA`: игровые строки,
ID/UUID, OID, FK, индексы, owned sequences и права сохраняются. Занятые чужие
схемы не присваиваются; ошибка откатывает изменения. Версия раскладки — 1;
версии схемы Planet 10, Chat 1 и формата табличного мира 1 не изменены.

Добавлен **`--check-schemas`** — проверка имён, конфликтов и прав CREATE в READ ONLY.
Она не запускает HTTP, симуляцию и миграции. [Структура, права, backup и порядок
обновления](../docs/operations/database-schemas.ru.md).

Перед обновлением: согласованный backup, остановка старых трёх служб, прежний
TOML и имя установки. Новый Cosmic запустить первым, после завершения миграции —
Planet и необязательный Chat. Backup после переноса должен включать **все** схемы
установки. Не смешивать старые и новые сборки. Для отката нужен backup.

Проверено на PostgreSQL 17: обновление настоящей установки 0.26.0 (226 OID и
контрольные суммы данных сохранены), повторный запуск, откат ошибки, FK/секции/
права, ограниченные роли, новые секции галактики и Chat. В Chromium прошли
высадка, мышь/WASD, ввод в Chat, коллизии, повторный вход и переходы секторов.

Cosmic, Planet и Chat выпущены для **Linux amd64 и Windows amd64**. Предыдущие
версионные сборки в `downloads` сохранены. Windows в этой среде не запускалась.
