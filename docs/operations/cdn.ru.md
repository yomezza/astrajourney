# AstraJourney CDN · 0.29.0

Четвёртая Go-служба `astra-journey-cdn` обслуживает графику из файловой системы,
поддерживает Core NATS и не подключается к PostgreSQL. Cosmic хранит HTML/CSS/JS,
игровые API, сессии и права; его binary больше не содержит изображений/текстур.
CDN также не содержит встроенной копии графики.

## Запуск и адрес игры

Самый простой вариант использует CDN как входной HTTP-шлюз. Браузер открывает
его адрес, например `http://127.0.0.1:8083`: графика передаётся напрямую из CDN,
остальные запросы, включая Planet/Chat gateways, направляются в Cosmic на
приватном `127.0.0.1:8080`. Отдельный nginx для локальной установки не требуется.
Для публичной игры HTTPS reverse proxy направляется в CDN; задайте действительный
`cosmos.public_origin`, `cookie_secure=true` и те же allowed_origins в Planet/Chat.
CDN заново формирует forwarding headers и не доверяет присланному браузером XFF.

Примеры: [общий TOML](../../configs/shared.example.toml),
[отдельный CDN TOML](../../configs/cdn.example.toml). Относительные пути CDN в
TOML разрешаются относительно CONFIG_FILE. В режиме окружения значения по
умолчанию: `CDN_HTTP_ADDR=127.0.0.1:8083`, `CDN_STORAGE_ROOT=data/cdn`,
`CDN_COSMIC_INTERNAL_URL=http://127.0.0.1:8080`, `CDN_SYNC_ENABLED=true`,
`CDN_REPOSITORY=yomezza/astrajourney`, `CDN_SYNC_INTERVAL=30m`.

Windows PowerShell, из каталога установки:

```powershell
$env:CONFIG_FILE = 'D:\AstraJourney\configs\shared.toml'
.\astra-journey-cdn-v0.29.0-windows-amd64.exe
```

Для Windows SCM предусмотрено имя службы `AstraJourneyCDN`. В PowerShell
администратора один раз создайте службу с полным путём EXE и задайте её CONFIG_FILE:

```powershell
New-Service -Name AstraJourneyCDN -BinaryPathName '"D:\AstraJourney\astra-journey-cdn-v0.29.0-windows-amd64.exe"' -StartupType Automatic
New-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\AstraJourneyCDN' -Name Environment -PropertyType MultiString -Value @('CONFIG_FILE=D:\AstraJourney\configs\shared.toml') -Force
Start-Service AstraJourneyCDN
```

Linux:

```sh
CONFIG_FILE=/etc/astra-journey/shared.toml ./astra-journey-cdn-v0.29.0-linux-amd64
```

Для systemd есть [готовый unit](../../configs/systemd/astra-journey-cdn.service).
Он рассчитан на учётную запись `astrajourney`, binary с постоянным именем
`/opt/astra-journey/bin/astra-journey-cdn`, CONFIG_FILE в `/etc/astra-journey/`
и storage_root `/var/lib/astra-journey/cdn`. StateDirectory создаёт корень с
нужным владельцем. После размещения unit выполните `systemctl daemon-reload`
и `systemctl enable --now astra-journey-cdn`.

CDN сам создаёт структуру внутри storage_root, локальный сервисный token и
скачивает готовую графику из опубликованного GitHub Release. Токен не выводится
в логи, не передаётся через NATS и не отправляется браузеру. Подготовьте один
доступный службе корневой каталог; внутренние папки вручную создавать не нужно.
Можно запускать службы от одной выделенной учётной записи ОС. При отдельных
учётных записях Cosmic должен иметь право чтения только service.token через
группу/Windows ACL, а CDN — права на своё хранилище. Имена/пароли NATS раздельные.

Рекомендуемый порядок: CDN, ожидание `/cdn/api/v1/health/ready` с HTTP 200,
Cosmic, затем Planet/Chat. Cosmic может стартовать до CDN: его экономика и БД
не зависят от готовности графики. До появления проверенного пакета readiness CDN
возвращает 503, HTTP-сервер остаётся доступным для диагностики.

## Где находятся файлы

```text
<storage_root>/
  public/packs/<revision>/
    manifest.json
    space/ships/                 SVG кораблей
    space/objects/               звёзды, планеты, станции, поля
    planet/pixelart-v1/           terrain, water, characters, construction,
                                 nature, effects, landing, assets, JSON
    ui/icons/                    значки интерфейса
    ui/branding/                 favicon
  private/guide/
    objects/<uuid-prefix>/<uuid>.png
    receipts/<uuid-prefix>/<uuid>.json
  staging/packs/                 загрузка/проверка пакетов
  staging/uploads/               временная запись изображений
  quarantine/guide/              резерв для ручной изоляции объектов
  state/
    catalog.json                 порядок установленных пакетов
    catalog.previous.json
    service.token
    owner.lock
```

Первые две hex-цифры UUID распределяют private-файлы по подкаталогам. Имена
UUID и ссылки руководства сохраняются. Состояния публикации и ACL находятся
в БД Cosmic; наличие PNG/receipt не означает, что файл доступен игроку.
Quarantine в БД закрывает доступ без автоматического перемещения/удаления файла.
Ни private, ни staging, ни весь public целиком не являются HTTP webroot:
служба раздаёт только разрешённые манифестом файлы и защищённый media-маршрут.
Один каталог принадлежит одному процессу CDN; вторая копия откажется от запуска.

Пути в конфигурации можно выбрать самостоятельно, например
`/var/lib/astra-journey/cdn` или `D:\AstraJourney\data\cdn`.
Подкаталоги пакетов и временные каталоги должны находиться на одном файловом томе
для атомарной фиксации. Перезапуск и обновление EXE не удаляют storage_root.

## Автоматическое обновление из репозитория

Сборка выпуска формирует `astra-journey-assets-<revision>.zip` и
`astra-journey-assets.json`. Источник — опубликованные GitHub Releases указанного
репозитория. Git, Node.js, токен GitHub и клонирование main на игровом сервере
не нужны. Неопубликованные изменения исходников не попадают к игрокам.

При старте CDN проверяет локальные пакеты. Синхронизация сначала обеспечивает
пакет своего релиза, затем проверяет latest release и дальше повторяется по
sync_interval. Поддерживаются только известные schema/client_contract. Сервис
скачивает архив во временный каталог, проверяет SHA-256 архива, ревизию манифеста,
каждый файл, MIME/размер, пути и aliases, затем фиксирует полный пакет. Повреждённый
или незавершённый архив не заменяет установленную графику. SHA-256 проверяет
целостность; источником доверия остаётся выбранный репозиторий и его издатель.

После первой установки работающая графика доступна без GitHub и NATS. Ошибка
обновления сохраняет прежние пакеты и отражается в readiness/логах. Архивы не
содержат исполняемых команд; CDN не обновляет собственный EXE и игровую БД.
Старые пакеты автоматически не удаляются: они нужны открытым вкладкам,
историческим иллюстрациям и откату. Контролируйте общий объём хранилища.

Для установки без Интернета остановите CDN и выполните один раз:

```sh
astra-journey-cdn --install-pack /path/astra-journey-assets-REVISION.zip
```

Затем запустите службу с `sync_enabled=false`. Эта же операция с сохранённым
пакетом выбирает его графику для следующих страниц. URL всех установленных
ревизий продолжают работать; физические файлы не перезаписываются.

## Кэш у игроков

Канонический адрес: `/assets/sha256/<file-sha256>/<relative-path>`.
Ответы GET/HEAD имеют `public, max-age=31536000, immutable`, ETag, MIME и nosniff.
SVG имеют подготовленный gzip, отдельный strong ETag представления и
`Vary: Accept-Encoding`; PNG повторно не сжимаются. Поддерживаются 304 и Range.
Файловые байты не хранятся второй полной копией в собственном Go-кэше: используется
обычная файловая раздача и page cache ОС.

При открытии страницы клиент один раз получает маленький asset-map с revalidation
и фиксирует его для этой страницы. Совместимый новый пакет может изменить графику
без пересборки Cosmic. Изменение одного файла меняет только его URL; прочие
текстуры продолжают использовать прежние записи браузерного кэша. Клиент проверяет
наличие требуемых логических ресурсов; при несовместимом наборе сохраняет свой
подготовленный сборкой каталог ссылок. Новые типы ресурсов/разметка атласа могут
требовать обновления клиента, одного скачивания пакета для этого недостаточно.

Старые SVG/PNG/texture URL направляются на закреплённые хеши. Неизвестный `?v=`
не подменяется последней графикой. Явные hash URL иллюстраций руководства остаются
закреплёнными, чтобы публикации не меняли содержимое произвольно.
Браузер может вытеснить свой кэш, пользователь — очистить его или принудительно
перезагрузить страницу. Уже находящиеся в свежем кэше файлы повторно не скачиваются
при обычном открытии; это проверяется настоящим Chromium без перехвата запросов.

## Закрытые изображения руководства

CDN принимает GET/HEAD `/api/guide/media/{uuid}` и перед чтением/304 обращается
к service-authenticated `/internal/cdn/v1/media/{uuid}/authorize` Cosmic,
передавая текущую сессию. Cosmic проверяет роль, видимость категории/публикации
и state=ready, возвращает разрешённые ID/хеш. Изображение читает и передаёт CDN.
`private, no-cache` сохраняет браузерные байты с обязательной проверкой доступа.
Положительного ACL-кэша в CDN нет. При отказе Cosmic доступ закрыт; публичная
графика продолжает работать. Обходной public URL по ID/хешу отсутствует.

Загрузку администратора авторизует Cosmic. Нормализацию PNG/JPEG/WebP в PNG,
лимит 8 MiB, статичный формат до 4096×4096, запись и проверку receipt выполняет
CDN. SVG из пользовательской загрузки не принимается. Одинаковая операция
повторяется безопасно; другие байты с тем же ID отклоняются. До metadata commit
полученный объект не опубликован. Cosmic выполняет сверку pending/ready через
receipt и удаляет только явно deleted и неиспользуемые объекты спустя 30 дней.
Неизвестные БД orphan-объекты сохраняются для восстановления/аудита; отдельная
автоматическая очистка orphan-файлов в этом выпуске не включена.

## Перенос существующей установки

1. Остановите прежние службы/новые uploads и сделайте согласованный backup БД
   и прежнего GUIDE_MEDIA_DIR. Не меняйте database.schema и журнал чата.
2. Подготовьте конфигурацию четырёх служб. Старые EXE могут не знать новых TOML
   секций: сохраняйте прежний config для отката.
3. Если есть загруженные изображения, до обычного запуска CDN выполните:
   `astra-journey-cdn --import-guide /old/GUIDE_MEDIA_DIR` с новым CONFIG_FILE.
   Команда копирует PNG, сверяет существующие байты, сохраняет UUID, формирует
   receipt и оставляет исходный каталог. Она не подключается к БД и не меняет ACL.
4. Запустите CDN, дождитесь пакета, запустите новый Cosmic (миграция 290 один раз
   обновит game_release до 0.29.0), затем Planet/Chat. Настройте адрес входа через
   CDN и проверьте руководство, высадку, загрузку и карточку служб.

Повреждённые исходные PNG останавливают импорт с отчётом. Не удаляйте прежние
файлы до проверки миграции. Backup включает БД и private objects/receipts одного
согласованного состояния. Public packs восстанавливаются из релизов.
Для отката к старому Cosmic учитывайте новые uploads после переключения: сначала
остановите записи и верните их в прежнее UUID.png дерево либо восстановите
согласованный backup. Откат только бинарника не возвращает private-файлы назад.

## NATS и диагностика

Отдельный профиль `[nats.cdn]` либо отдельный `[nats]` с identity/username `cdn`.
Поддерживаются nats://, TLS, reconnect и ограниченные очереди; пароли служб разные.
Минимальные дополнительные ACL:

| Учётная запись | Publish | Subscribe |
|---|---|---|
| cdn | cosmos.v1.signal.cdn.assets.ready; cosmos.v1.signal.cdn.assets.changed | cosmos.v1.signal.cosmic.media.changed |
| cosmos | дополнительно cosmos.v1.signal.cosmic.media.changed | прежние subjects сохраняются |

Сообщения содержат метаданные envelope v1: UUID сигнала, источник, время,
ревизию пакета либо media ID/state. Ни файлов, ни токенов/сессий, ни путей в них
нет. Core NATS не является очередью гарантированной доставки: права проверяются
через Cosmic, файлы и пакеты — через устойчивое хранилище и периодическую сверку.
Сигнал media.changed учитывается в диагностике, не даёт права чтения/удаления.

Readiness: `/cdn/api/v1/health/ready`; каталог: `/cdn/api/v1/catalog`;
карта ресурсов: `/cdn/api/v1/asset-map`. В окне «Службы» есть карточка CDN.
`/cdn/api/v1/metrics` требует service token в X-Astra-Service-Token и содержит
счётчики байтов/запросов/304/ошибок, hints, память и диагностику NATS.
Не публикуйте token в командной строке/скриншотах; используйте защищённый
внутренний мониторинг. Для нескольких CDN узлов каждый должен получить пакеты,
а private-файлам требуется отдельное согласованное хранение/репликация. NATS
сам по себе файлы между узлами не копирует.
