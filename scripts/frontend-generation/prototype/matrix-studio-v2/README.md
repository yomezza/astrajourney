# MATRIX × STUDIO 2.0 · прототип

Из корня репозитория запустите `python3 -m http.server 18765 --bind 127.0.0.1`.
Откройте `http://127.0.0.1:18765/scripts/frontend-generation/prototype/matrix-studio-v2/`.
Прототип использует локальные тестовые данные, существующий русский словарь и графику из репозитория. Для сборки рабочего Web каталог не используется.

## Что можно проверить

- Реестр M001–M003 и единый рендер семейства в плитке и временном окне. Размещение выбирается в каталоге. Один тип можно добавлять повторно, в том числе с разными объектами.
- Плитки следуют кораблю пространства или фиксированному объекту. Для производного склада окно запоминает корабль, от которого была вычислена станция. При отсутствии стыковки показывает причину. Временные окна переживают переключение вкладок и закрываются при обновлении страницы.
- Плитки, ширина, порядок, привязки, вкладки, фильтры и черновики маршрута сохраняются локально. Корабль пространства опционален. Раскладка демо отделена от сохранений игры. Используется лимит 10 пространств и 16 плиток.
- Корабль показывает сводку, сравнение характеристик и оснащение. Инвентарь поддерживает трюм и два вида складов, таблицу, сетку, поиск, фильтры и сортировку. Навигация рисует схему по гиперлиниям тестового мира, позволяет добавлять, переставлять и удалять точки. Локальный режим показывает объекты в текущей системе.

## Граница интеграции

[Контракт Backend](https://github.com/yomezza/astrajourney/blob/cdcf9dc38c85f2b3c240dd952561771a6c44f4ce/docs/api/matrix-studio-v2.ru.md) опубликован отдельным коммитом `cdcf9dc`. Эта ревизия добавляет документ, реализация API v2 в ней отсутствует. Идентификаторы семейств, purpose и варианты отображения сверены с контрактом. Локальный формат прототипа не предназначен для передачи в API. Прототип не отправляет запросы на игровой API, кнопки мутаций отключены. Использованные структуры примеров не являются предлагаемыми DTO.

Действующие Studio, флот и карта зависят от общего snapshot активного корабля. Перед подключением нужны согласованный формат раскладки и миграция, загрузка привязанных объектов и возможностей с проверкой прав, адресованные выбранному кораблю команды и серверный предпросмотр маршрута. Отдельно нужны данные о базовых и фактических характеристиках, доступных слотах, складах, разрешённых назначениях, условиях перелёта, посадки и спасения. После появления контракта остаются интеграция существующих игровых инструментов и стартовой сводки операций, сценарии форм действий, серверных отказов, отзывов прав, повторов, stale/loading, выхода и проверка Chat, Notifications и Planet Mode. Код рабочего интерфейса в этой ветке не подключён к прототипу.
