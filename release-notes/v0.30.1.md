# Astra Journey 0.30.1

**Подготовленный выпуск, ещё не опубликован.** Только Linux amd64.

Отдельная публикация 0.30.1 не выполнялась. Эти исправления включены в
публичный [выпуск 0.30.2](https://github.com/yomezza/astrajourney/releases/tag/v0.30.2)
вместе с последующими оптимизациями; для обновления используйте его.

Исправлены повторные заставки загрузки при фоновом обновлении и обработка
всплесков запросов чата. Общая оптимизация остальных игровых подсистем в этот
выпуск не входит.

## Модули

- Уже открытые окна обновляются через общий тихий механизм: без заставки,
  блокировки содержимого и перехвата фокуса. Загрузчик сохраняется при открытии
  модуля, смене представления и первоначальной подготовке ресурсов.
- Фоновые обновления одного окна объединяются и отменяются при закрытии или
  новом открытии. Поздний ответ не должен возвращать старое представление.
- Карта системы больше не открывает себя заново при каждом обновлении данных
  и не обновляется под открытой поверхностью планеты.

## Чат

- Повторные обновления и одинаковые GET объединяются. Всплески распределяются
  по времени; после 429/503 чтение повторяется с задержкой. Закрытый чат не
  загружает историю, при возвращении состояние обновляется.
- Сервер сохраняет предел 64 активных HTTP-обработчиков. До 64 дополнительных
  запросов могут подождать не дольше 250 мс; постоянная перегрузка получает
  429 с Retry-After. WebSocket-команды не отправляются повторно автоматически.
- JSON сжимается gzip. Неизменившиеся представления можно получить через 304;
  копии хранятся только в памяти текущего клиента. Авторизация выполняется
  заново, `Cache-Control: no-store` сохраняется.
- Чтение outbox использует отдельные ограниченные диапазоны новых ID и
  временного overlap. Для движущихся границ план строится на каждый вызов,
  чтобы generic plan не заставлял перечитывать всю сохранённую историю.
  Поздние COMMIT, проверка прав и периодическая сверка состояния сохраняются.

## Обновление с 0.30.0

Сохраните свой конфиг, `database.schema`, каталоги Web/CDN, service token и
существующий журнал Chat. Замените пять Linux-бинарников. Первым запускается
Cosmic, затем Planet, Chat, CDN и Web. Адреса, режим Chat/NATS и пулы соединений
автоматически не меняются.

Миграция 301 один раз устанавливает общую отображаемую версию игры **0.30.1**
в `game_release`. Менять версию отдельно на страницах не требуется. Дальнейшие
операторские изменения версии переживают обычные перезапуски. Новых таблиц
или индексов для игровых данных нет.

**Новый Web-пакет обязателен.** Если задан `[web].release_tag`, замените
`v0.30.0` на `v0.30.1`. Автосинхронизация станет доступна после публикации
релиза. До публикации пакет из подготовленного комплекта можно установить:

```sh
CONFIG_FILE=/etc/astra-journey/config.toml ./astra-journey-web-v0.30.1-linux-amd64 --install-pack /path/to/astra-journey-web-REVISION.zip
```

Используйте фактическое имя ZIP из `astra-journey-web.json`. После активации
обновите страницу игры, чтобы загрузился новый интерфейс.

**Графика не менялась:** её revision и адреса файлов прежние. Повторная ручная
установка CDN-пака на существующем хранилище не требуется; в комплекте пак
остаётся для новой установки.

## Состав и ограничения проверки

Пять статических Linux amd64 ELF, build manifest, ZIP интерфейса и графики,
два JSON-индекса, шесть примеров TOML и SHA256SUMS. Node.js/Python для работы
служб не требуются.

Новые тесты и нагрузочные прогоны при подготовке выпуска по просьбе владельца
не запускались. Более ранние UI/Chat-проверки и границы их применимости описаны
в [handoff исправлений](../ai/handoffs/backend/009-chat-background-refresh.ru.md).
Последний нагрузочный прогон был остановлен по просьбе владельца; подтверждённой
новой оценки вместимости сервера после исправлений нет.
