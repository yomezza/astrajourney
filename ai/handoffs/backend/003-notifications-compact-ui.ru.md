## Реализовано

- Стартовый размер окна 420 × 540, компактная штатная шапка с индикатором и счётчиком, строки с тематическими иконками, временем, заголовком и сокращённым текстом. Цвета, плотность и квадратные углы соответствуют варианту A.
- Внутренняя прокрутка, группы прочитанных/непрочитанных, фильтры «Все»/«Непрочитанные», кнопка «Прочитать всё», меню массовых операций. Выбор записей включается через меню; отдельную запись можно прочитать кнопкой ✓ или через подробности, удалить через подробности/контекстное меню.
- Подробности с полным текстом открываются внутри существующего окна. Поддержаны клавиатура, удержание фокуса внутри подробностей, Escape и возврат фокуса к записи. Текст вставляется безопасно через DOM, без интерпретации пользовательского HTML.
- Счётчики в верхней панели игры и заголовке окна используют серверный `unread`, скрываются при нуле и показывают `99+` при значении больше 99.
- Реальные данные и сохранение через существующий API. После записи запрашивается свежее состояние; старый параллельный snapshot не возвращает уже прочитанную запись.
- Защита от повторной отправки на время операции. При неудачной записи запись не удаляется и не считается прочитанной; штатное сообщение об ошибке, возможность повторить действие. Фильтр и по возможности прокрутка сохраняются.
- Проверки `Session.signedIn` / `Session.epoch`: данные, выделение и подробности очищаются при выходе. Поздние ответы прежней сессии не возвращают её уведомления в новый аккаунт.
- RU/EN для новых подписей, относительного времени, пустых состояний и доступных названий элементов.
- Штатные перемещение, resize, pin, закрытие и слои остаются в `Modules`. Устранено специальное принудительное позиционирование уведомлений, мешавшее восстановлению расположения. Только этому окну разрешена ширина содержимого от 300 px; порог остальных модулей сохранён.

## Контракты и ограничения

| Операция | Существующий контракт |
|---|---|
| Чтение | `GET /api/notifications` → `items`, `count`, `unread` |
| Прочитать одну / выбранные | POST `{"action":"seen","ids":[...]}` |
| Прочитать все записи пользователя | POST `{"action":"seen","ids":[]}` |
| Удалить выбранные | POST `{"action":"delete","ids":[...]}` |
| Очистить все | POST `{"action":"clear"}` |

Сервер по-прежнему отдаёт последние 500 записей. Интерфейс явно показывает «Показаны последние … из …»; фильтрация и выбор работают с загруженными записями. Если непрочитанные остались за этим пределом, фильтр сообщает об ограничении, а не утверждает, что непрочитанных нет. Кнопка «Прочитать всё» обрабатывает **все серверные записи**, включая более ранние. Пагинация API не добавлялась.

| `kind` | Визуальная категория |
|---|---|
| `research_complete` | Исследования |
| `delivery_complete` | Экономика |
| `company_invitation`, `project_complete`, `colony` | Корпорация |
| `arrival`, `landing_ready`, `mining_complete`, `portal_open` | Игровые |
| `message`, неизвестный тип | Системные |

Действия «На карте», «Корабль», «Трюм», «Открыть поверхность» и «Открыть проект» сохранены. Открытие подробностей **не вызывает** `select_ship`. Эта команда вызывается только явной кнопкой «Корабль», с прежними серверными проверками.

Производственные Go-обработчики, PostgreSQL/миграции, API, NATS, конфигурация служб и файлы чата не изменялись. Новый Go-файл — исключительно интеграционный тест; в `internal/server/app.go` изменён только номер версии Cosmic. Дополнительных WebSocket или подключений к Chat Service не создаётся. Демонстрационные данные находятся только в тестах; production получает уведомления из API.

## Проверки

Для серверных сценариев использована отдельная тестовая PostgreSQL с временной схемой и последующей очисткой. Рабочая БД не подключалась. Браузер — Chromium на Linux.

1. Автономный прототип из отдельной ветки: `node test_contracts.cjs` и `python3 test_prototype.py` — **PASS**. Визуально сопоставлен вариант A.
2. `RUN_NOTIFICATIONS_BROWSER=1 go test ./internal/server/integration -run '^Test(NotificationsCompactBrowser|033ResearchDataAndNotifications)$' -count=1 -timeout=4m -v`, с `TEST_DATABASE_URL` отдельного тестового стенда — **2 PASS**.
   - Настоящие HTTP API и PostgreSQL, без перехвата API в браузере. 516 записей на сервере, 500 в ответе; пять категорий и неизвестный `constructor`, длинный текст с HTML-подобной строкой, пустой список и непрочитанные за пределами 500.
   - Отметка одной, выбранных и всех записей, удаление одной/выбранных, очистка; точные серверные `count`/`unread`. Попытки прочитать/удалить чужую запись не меняют её.
   - Все игровые переходы, явный выбор корабля, отсутствие выбора корабля при открытии подробностей; поверхность и проект используют реальные тестовые игровые объекты.
   - Размеры 420 × 540, 360 × 420 и 320 × 360, прокрутка и её граница без прокрутки страницы, перемещение, закрепление/снятие закрепления, восстановление геометрии при закрытии/открытии.
   - Фокус подробностей сохраняется при обновлении snapshot, Escape закрывает подробности, но оставляет модуль открытым. RU/EN, смена аккаунта, отсутствие ошибок страницы/HTTP и дополнительных сокетов в данном сценарии.
3. `node --test --test-concurrency=1 tests/ui/notifications.test.mjs tests/ui/chat-layout.test.mjs tests/ui/lifecycle.test.mjs tests/ui/architecture.test.mjs` — **15 PASS**.
   - Четыре новых сценария уведомлений: ошибка POST с повторным нажатием/повторной попыткой; старый snapshot после успешного прочтения; поздний GET и поздний POST после выхода/смены пользователя. Ошибки и задержки намеренно воспроизводятся на тестовом HTTP-стенде.
   - Существующие проверки чата, жизненного цикла модулей и графа JS-зависимостей. Проверка чата использует штатный browser-harness с моделируемым протоколом; отдельный многосервисный Chat/NATS-стенд в этой задаче не поднимался.
4. `git diff --check` — **PASS**.

Полная многосервисная и нагрузочная проверка, запуск Windows-процесса и полный набор всех Go-тестов не выполнялись. Настоящие браузерные операции проверены локально; состояние GitHub Actions следует проверять у PR, отдельно от этих результатов.
