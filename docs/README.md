## Как выбирать источник истины

1. **Текущее поведение:** подтверждается в `main`, тестах, актуальном API и релизных материалах. В старых `docs/ideas/` могут оставаться исторические ограничения или названия.
2. **Принятая архитектура и эксплуатация:** смотреть фактические контракты, профильные документы и состояние соответствующего этапа в `docs/operations/`.
3. **Новая идея:** исходный документ в [реестре идей](ideas/README.md). Наличие README или mock-версии **не означает внедрения**.
4. **Промпт ИИ:** в [`ai/prompts/`](../ai/prompts/README.md) лежит **задача**, а не отчёт о её выполнении; `handoff` фиксирует проверенный результат.

## Чего пока не делали

Это **навигационная уборка** без переименования старых путей. Каталоги `docs/refactoring/`, `docs/chat-service/`, `docs/planetary/` и `docs/operations/` остаются на местах: перенос потребует аудита ссылок и истории релизов.

Бинарники в `downloads/` и конфигурации workflow не трогаем: действующая схема выпуска использует эти файлы. Пересмотр релизных артефактов — отдельный этап с проверкой сборки.

## Как добавить документ

- Новую концепцию создавай в `docs/ideas/<short-slug>/README.ru.md` и добавляй в [реестр](ideas/README.md). Название каталога выбирай по **идее**, не по имени чата.
- Технические материалы внутри неё называй осмысленно, без обязательного переименования уже существующих документов.
- Проверяй относительные ссылки от каталога файла.
- Указывай статус и отдельно **не реализовано / реализовано на mock / реализовано в игре**, при возможности — ссылку на код, тест или release note.
- Задание ИИ размещай в `ai/prompts/<role>/<NNN>-<slug>/prompt.md`; один источник концепции — в `docs/ideas/`.

Изменение статуса идеи требует проверки и ссылки на подтверждающую реализацию, а не просто заявления исполнителя.
