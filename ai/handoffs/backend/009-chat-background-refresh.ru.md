# Чат и тихое фоновое обновление модулей

**Статус:** изменения в коде завершены. Владелец сузил исходное поручение:
общую оптимизацию игры отменил, оставил фоновое обновление всех модулей и работу
чата при большом онлайне. Позднее явно попросил продолжать **без проверок**:
запущенный нагрузочный прогон остановлен, дальнейшие проверки не выполнялись.

Ветка `fix/chat-and-background-refresh`, основание — локальный baseline
`7315d64`. Публикации, push, изменения версии или production не было.
Подготовительные правки Fleet, Workbench, Worldstore, Planet и общего
Cosmic-compression были полностью убраны после уточнения области задачи.

## Изменения

- `web/ui/module-loading.js`, `windows.js`: добавлен `Modules.update(id, work)`
  для уже открытого окна. Нет заставки, `inert`, смены фокуса или повторного
  открытия. Обновления объединяются; закрытие/новая foreground-загрузка отменяет
  фоновые задачи. Foreground `prepare/open/load` сохраняет прежнюю загрузку
  ресурсов. Callback получает AbortSignal и может вернуть false, если результат
  не применён; фоновые вызовы не должны использовать `Modules.load`.
- `web/features/workspace/index.js`: постоянные обновления окон используют общий
  тихий механизм с существующими ограничениями для редактируемых форм.
- `web/features/maps/galaxy.js`: системная карта обновляется без повторного
  `Modules.load`. Не обновляется под открытой поверхностью; старый ответ не
  переключает окно обратно на карту и не перехватывает фокус других модулей.
- `web/features/chat/refresh.js`, `index.js`: один refresh одновременно,
  объединение всплесков, небольшой разброс старта и повтор чтения после 429/503.
  Закрытый чат не загружает историю; при возвращении обновляется состояние.
  Отправка WS-команд и обработка неопределённых ACK не менялись.
- `web/features/chat/transport.js`: одинаковые GET объединяются; до 32 ответов
  хранятся только в памяти текущего клиента для условных запросов. Ошибки доступа
  не подменяются кешем; закрытие аккаунта очищает данные и отменяет запросы.
- Chat HTTP: gzip для JSON и условные ETag-ответы. Авторизация и SQL выполняются
  перед решением о 304; `no-store` сохраняется. Общий Cosmic middleware не менялся.
- Chat admission: максимум 64 активных HTTP-обработчика; ещё до 64 ожидают не
  дольше 250 мс. Постоянная перегрузка по-прежнему даёт 429 с Retry-After.
- Chat outbox: новые ID и временное overlap-окно читаются раздельно, каждый
  диапазон ограничен страницей. Для движущихся границ отключено повторное
  использование named generic plan только у этого запроса. Старый индекс
  `(created_at,id)` сохранён; DDL, миграций и смены режима NATS нет. Поздние
  COMMIT и периодическая сверка состояния не убирались.

## Что успело выполниться до остановки проверок

- Полный UI-набор: **90 PASS**, включая восемь одновременно открытых модулей,
  сохранение фокуса, поздний ответ системы поверх планеты, объединение и отмену
  фоновых обновлений, сохранение первоначального загрузчика.
- После изменения чтения закрытого чата: целевой UI-набор **13 PASS**.
- HTTP/Chat unit + race: PASS. Проверены gzip/304, неизменённый WebSocket writer,
  краткий всплеск из 100 HTTP-запросов с пределом 64 активных и отказ при
  постоянной перегрузке.
- Chat 240: транзакции, restricted role, поиск, корпоративные fences, поздние
  записи и 50 соединений прошли. После исправления типов границ SQL повторные
  N1 recipients/paging и B1 late-COMMIT-beyond-overlap прошли.
- Проверка на 200000 старых + 200 недавних строк: обычный и per-execution план
  использовали 9 shared blocks; принудительный named generic — 2025. Это причина
  выбора per-execution режима, а не удаления overlap или добавления индексов.
- Собраны только локальный Linux Chat и пробный Web-пакет в
  `dist/chat-background-fix/`. Это промежуточные артефакты, не финальная поставка.

**После команды «без проверок»** внесены только завершающие исправления:
сохранение callback=false в тихом обновлении и освобождение места очереди сразу
после допуска HTTP-запроса. Эти финальные строки не проверялись и не пересобирались.
Полный UI-набор также не повторялся после последнего изменения закрытого чата;
для него был отдельный целевой повтор, указанный выше.

Новый native-прогон с logging/NATS b1 был начат с четырьмя прежними релизными
службами, новым Chat и пробным Web-пакетом. По просьбе владельца он остановлен;
**завершённого результата при 100 игроках нет**. Не выдавать его за успешный
capacity-тест или сравнение с прежними 31,6% ответов 429.
Локальный каталог `dist/mixed100/20261118T043444.517112599Z/` помечен
`cancelled_by_user`. Его дочерние процессы остановлены, временная БД и две её
служебные роли удалены. Исходный baseline 17 ноября сохранён.

В `mixed100_test.go` оставлены необязательные пути к локальным Chat/Web
артефактам для будущего сравнения; действуют только внутри `dist` репозитория.
Новые тестовые файлы сохранены, но повторно запускать проверки без следующей
команды владельца не нужно. Игровые правила, деньги, скорость и настройки
действующих служб в рамках этой работы не менялись.
