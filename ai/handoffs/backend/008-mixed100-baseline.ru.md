# Смешанный baseline 100 игроков · 0.30.0

**Статус:** эксперимент выполнен, обнаружена деградация Chat. Основание — новая
команда владельца симулировать 100 игроков с логированием всех служб. Разрешения
на внедрение оптимизаций или новый релиз в этом этапе не было.

Ветка `experiment/mixed-100-players` продолжает локальный план `cd29786` и
диагностику `3edcb26`. Игровой runtime — точные опубликованные Linux amd64
бинарники 0.30.0, источник `8bcbad894d5516addb1544586226257fae12fa97`;
SHA-256 пяти файлов сверены с build manifest. Ничего не отправлялось в remote.

- [Подробный отчёт и ограничения](../../../docs/qa/mixed100-0.30.0.ru.md).
- [Инструменты и запуск](../../../tests/load/README.ru.md).
- Opt-in Go-драйвер: `internal/server/integration/mixed100*_test.go`.
- Компактные JSON и графики: `docs/qa/mixed100-0.30.0/`.
- Полные логи и наблюдения: локально `dist/mixed100/20261117T124245.096651128Z/`;
  архив журналов примерно 351 MiB, не включать в Git.

Новая loopback-БД, NATS 2.12.3 TLS/ACL, все пять служб с diagnostics. Chat b1,
пулы по 8, общий cgroup 4 CPU / 32 GiB. 25/50 игроков по минуте, 100 — 30 минут;
30 на поверхности, 80 пишущих с интервалом 15–25 с. 99 протокольных клиентов и
один настоящий Chromium входят в число 100. Тест и процессы остановлены, БД
удалена; production не использовалась.

Основной этап: 1 176 578 HTTP, 0 HTTP 5xx/transport, 0 неожиданных WS-разрывов.
**269 157 ответов 429**: 31,6% запросов bootstrap/notifications/history Chat.
Общий admission limit 64 запросов, массовые refresh и SQL-пул 8 создают отказы.
Все 7363 сообщения подтверждены и найдены в БД, хотя это не подтверждение
своевременного обновления у каждого получателя. 19/19 задач завершены,
отрицательных балансов/груза не обнаружено. 2564 ответа 409 — квота добычи.

Средний общий CPU 3,32/4; серверная группа с БД около 2,80 ядра. PostgreSQL
1,624, Cosmic 0,569, Chat 0,285, Web 0,216, Planet 0,107. Логи 4,46 GiB.
p95 snapshot терминала 189 мс, движения 124 мс, Chat ACK 197 мс. Это не оценка
максимального онлайна и не замер сервера владельца.

CPU PostgreSQL на 100 игроках вырос с 1,17 ядра в первые пять минут до 2,01
в последние пять минут при снижении HTTP RPS. Конкретный SQL как причина не
установлен; профилировать в том числе повторное чтение outbox и рост истории.

`go test` PASS подтверждает выполнение сценария; поведенческий результат имеет
серьёзные отказы Chat. В конце статистики также 2 внутренних дедлайна Planet
на shared world-lock и один отменённый браузером SQL-запрос Cosmic; см. отчёт.

Ограничения: новая история, одна планета, общий старт; часть добытчиков исчерпала
квоту, навигаторы — топливо, у планировщиков одна задача. Browser v1 не раскрывал
меню карты и пропускал кнопки вне sidebar; таймауты не считать ошибкой продукта.
Его финальный JSON — периодический снимок. Дерево PostgreSQL/Chromium/NATS для
первого baseline брать из дополнительного `process-trees.jsonl`: исходный helper
не поддержал виртуальный `/proc/task/children`. Эти ограничения исправлены в
будущем драйвере, полчасовой baseline после исправлений не повторялся.

Проверено: короткий 20-player pilot PASS, полный 100-player PASS с указанной
деградацией, SHA-256 релизных файлов, media burst 680/680 и 11 ETag 304,
финальная сверка БД, очистка; компиляция/синтаксис инструментов и diff check.
Полные регрессии продукта не запускались. Только Linux, без новых сборок,
изменения runtime, SQL-миграций, production-конфига или публикации.

Следующий шаг по команде владельца: оптимизация Chat/клиентского refresh с
сравнением по этому baseline. Не повышать лимиты вслепую; сначала убирать
повторную работу, затем проверять запросы/индексы и общие world-lock.
