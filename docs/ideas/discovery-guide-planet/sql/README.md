## Перед будущей интеграцией

1. Сделать backup/PITR, проверить PostgreSQL/DB_SCHEMA, выполнять SQL только на отдельной тестовой базе.
2. Проверить JSON `galaxies(name='Edem').data->'stars'`, ID всех систем/планет, уникальность имен, founder_key/companies, планетарные поверхности. Документировать весь preflight.
3. Выбрать **единый** Unicode normalizer для поля name_key; в драфте SQL seed использует lower(trim), будущий Go должен обеспечить согласованность с NFKC+casefold. Исправить/пересчитать seed keys **до** открытия API переименования. Коллизии при создании UNIQUE index должны привести к безопасной остановке миграции.
4. `surveys.source` отличает личное исследование от полученных сведений, но исторических timestamps полного первооткрытия нет. Драфт консервативно ставит `legacy_unattributed` для уже изученных объектов, не назначает игроков случайно.
5. Проверить безопасность конкурентного изменения дерева категорий: триггер и Go должны сериализовать structural edits, проверить cycle races на PostgreSQL.

7. После утверждения скопировать SQL в `internal/server/schema250.sql` или следующий свободный номер, добавить файл в embedded schema FS и в Cosmic миграционный runner; проверить пустую и обновлённую тестовые БД. SQL применяется только владельцем миграций.

## Rollback

После появления пользовательских имён и статей нельзя автоматически DROP таблицы: это потеря данных. Выключить feature flag, оставить additive schema. Если требуется физический откат — восстановить согласованную БД + файлы медиа и повторно сверить события, безопасно сохранять уже опубликованный контент. Полный rollback SQL не публикуется как безопасная операция.
